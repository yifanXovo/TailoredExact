# Conditional G3 runner handoff — source only

Files: [`scripts/round89_native_b1_g3.py`](../../scripts/round89_native_b1_g3.py) and [`preregistration_g3.json`](preregistration_g3.json). This preparation has **not** invoked the runner, Python compile, tests, model export, build, Optimize, or heavy audit. It is parked if Round89 qualification fails. Existing Round88 runners/helpers and the nine frozen qualification files were not edited.

The panel has eight preselected roles, two **contemporary arms on one newly qualified binary** per role, and 16 total runs. E8/S12 use 120 s each, D3/C2 600 s, D7/U6/F5/F6 1200 s; total maximum process caps are 12,480 s. Order is E8 ENS/B1, S12 B1/ENS, D3 ENS/B1, C2 B1/ENS, D7 ENS/B1, U6 B1/ENS, F5 ENS/B1, F6 B1/ENS. Smoke contains four arms; rest contains twelve. Input files, scenario parameters, seed 0, threads 1, Presolve Auto, affinity mask 4, native limit offset 6 s, hard stop offset 2 s and shutdown margin 3 s inherit the Round88 preregistration. Both arms retain the complete ENS-C 24+1 startup and proof. The only arm difference is explicit `--round89-native-ot-b1 false|true`; no Round88 A1 flag. The preregistration separates P's canonical ancestry (`source_round` 83/85/87) from the actual Round88 P timing receipts, with exact paths and launch/audit hashes. Round88 P is historical, unpaired context; no P timing is newly run or pooled with the Round89 same-binary pair.

**No implicit execution permission.** The preregistration names the current source commit and binary hash as *provisional*. Root must review the completed qualification receipt, update these two prereg fields if qualification repair changed them, then create `results/unified_exact_round89/g3_qualification_gate.json` with schema `round89-native-b1-g3-qualification-gate-v1`, `authorized_by="root"`, `qualified=true`, `allow_prepare=true`, `allow_optimize=true`, exact prereg/runner/binary hashes, final source commit, final nine-file `source_hashes`, `qualification_receipt_path` and its SHA, and the exact `harness_hashes` mapping computed by the reviewed runner. A gate that only repeats an intermediate test-source hash is invalid. The runner verifies each hash before preparation and again before every stage. Preparation creates a new, non-overwritable campaign identity and the 16 exact commands; no Optimize occurs then. Root separately creates `runner_smoke_lease.json` with schema `round89-native-b1-g3-stage-lease-v1`, stage `smoke`, identity SHA, `authorized_by="root"`, `allow_optimize=true`. After four smoke audits and independent review, root writes `runner_smoke_gate.json` (`round89-native-b1-g3-smoke-gate-v1`, smoke_runs 4, exact summary SHA, accepted true) and a **new** `runner_rest_lease.json` with stage `rest`. No lease is generated by the runner itself. This is a contract for future root review, not a request to issue those files now.

The runner reuses the audited Round88 read/hash/write/memory/bound-preview utilities, Round70 affinity, Round86 journal/physical/bound replay and Round83 neutral-exchange replay by normal imports; it does not monkeypatch historical files or relabel their results. It records input, source, binary, prereg, reader/harness hashes, exact commands, start/prelaunch/wrapper/process/offline-audit cost, all committed event receipts, peak-safety samples, completed/unknown statuses and original physical/certificate/coverage evidence. It checks original-problem cross-arm bound contradictions without merging endpoints. The same preregistered severe certification-time, severe certificate-loss and severe open-gap signals stop the next role pending review; resource/identity/audit failures stop immediately. There are no retries, overwrite, automatic expansion or per-component time/Work slices.

For the native-B1 arm, every completed proof MIP's `<native_log>.round89.ot_b1.summary.json` must join **exactly one** `paper_optimize_ledger.csv` call by full native-log path, leaf, solve kind and model SHA. The summary's model scope/row signature must be present and consistent whenever its model SHA recurs. Normal completion requires unique native-log identities, an exact summary-to-ledger bijection and agreement with the result's partial-plus-terminal MIP count. The current `models/<leaf_id>.lp` is independently SHA-verified if it still matches that call. A verified-incumbent epoch can rebuild that leaf path; then the runner requires a later same-leaf ledger call with the new current-file SHA and records `old_epoch_lp_bytes_unavailable_ledger_identity_only`. It never attributes the new bytes to the old call. The production solve path checks the imported canonical SHA/matrix at call time, but this development screen does **not** contain complete per-epoch LP byte archives, so old-epoch retrospective LP replay is unavailable. Zero MIP calls are `not_exposed_zero_mip_calls`, not cut ineffectiveness. At a hard kill, only summaries with unambiguous ledger matches contribute known completed counts; missing/inflight summaries and the **total** callback count/time remain unknown. `GRBcbcut` API success is not proof that a cut was retained or caused a bound gain. Only original physical replay and scoped evidence audit determine usable U/L and certificate.
