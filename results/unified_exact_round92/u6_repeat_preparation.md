薄包装器以独立 module object 加载已审 G3 runner，复用 `command_for`、`run_one`、物理/证据 replay、candidate 行与 Optimize SHA join、同组 cross-arm 审计；仅将命令中唯一 `--gurobi-seed 0` 改为 1 或 2。冻结 R86 evidence reader 原本把每个 native call 的 `settings.Seed` 硬定为 0；新脚本明确用只属于此独立 module object 的 seed-aware evidence adapter：先对**原始**每个 call 严格核整份 settings 字典，包含 Seed=当前 1/2 和所有其余原容差/参数，再在内存浅拷贝中仅将已验证的 Seed 投影为 0，交原 R86 reader 完成其余物理/覆盖/界检查。原始 journal、receipt SHA、`observations.json` 都不改，`audit.json` 记录投影及原始 call 数。每条正常结果还必须直接查 C++ `result.json` 的 Gurobi Seed requested/effective、set/get 返回码，同时核 Threads、Presolve、candidate 身份及已完成的 25 个 decoded descent 起点。单看 CLI seed 不算验收。无正常回执、native seed/物理/coverage/数值/模型身份/进程或资源故障立即停止并留完整已付 prefix。每个 seed 的性能风险行照实记录，却不中断另一预定 seed；四臂完成后无论结果均收口，不恢复 F5/F6。

只有同 seed 两臂正常、审计通过且均保持 open，才能比较绝对 gap。三个 seed **全部**属于同类 open 配对时，按预注册线 `gap_H > 1.5 gap_ENS` 且差 `>0.01` 核：至少两 seed **各自同时**跨过两项原严重信号阈值、至少两 seed 的差同向向上，且三 seed 的 `gap_H−1.5 gap_ENS` 中位数大于 0、`gap_H−gap_ENS` 中位数大于 0.01，记风险复现；未越线记该固定复核未复现。若某 seed 一臂或两臂认证、删失或失效，分别呈报认证时间/未知，不把认证时间与 open gap 拼接成中位数，结论为不可同类比较。此为开发风险复核，不能从三 seed 推断统计显著性或算法晋升；失败和正负结果全部保留。
