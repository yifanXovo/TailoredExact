# Native user-cut API boundary: primary-source check

Root checked the Gurobi 13.0 reference documentation on 2026-09-27, in addition to the local source/header audit.

- `GRBcbcut` is restricted to MIPNODE callbacks. Its cuts must preserve every integer solution satisfying the original model; a nonzero API return indicates a submission error. The documentation also warns that added rows can slow node processing. It does not promise that every successful call becomes a permanently active row. [C callback reference](https://docs.gurobi.com/projects/optimizer/en/current/reference/c/callback.html#c.GRBcbcut)
- `PreCrush=1` disables some presolve reductions to help transform original-model cuts into the presolved model. Otherwise an untransformable cut may be ignored. This setting changes presolve behavior and must be recorded and costed. [PreCrush reference](https://docs.gurobi.com/projects/optimizer/en/current/reference/parameters.html#parameterprecrush)
- Read `MIPNODE_REL` only when the node status is OPTIMAL, using a buffer for the original user-model column count. The returned point is not necessarily feasible for that user model. Root MIPNODE events recur across cut passes while the node count remains zero. [Callback codes](https://docs.gurobi.com/projects/optimizer/en/current/reference/numericcodes/callbacks.html)

Design implications, subject to independent review: a B1 signed inequality remains integer-valid for any chosen signs, so an imperfect callback point can still select a valid inequality. Callback-point feasibility and cut validity are different checks. A successful submission must not be logged as a permanently active cut; recurrence of its violation is not automatically a numerical failure. Do not introduce a callback-pass or row cap to emulate a resource budget, and do not use lazy constraints for this already-valid strengthening family. Native acceptance, column mapping, numerical safety and actual cost still require qualification before an implementation is trusted.
