# Round90 LP-G split: candidate-only method delta

Round90 adds `--round90-lp-g-split true|false`, false by default. It is accepted only with `--method gcap-frontier --algorithm-preset research-round83-vds-equal-net-exchange`, without Round88 A1 or Round89 native B1. The effective result, emergency and run-config identity is `research-round90-ensc-lp-g-split`; the internal Round83 preset still supplies the original 24+1 startup and controller. With the flag off, the original midpoint path and output schema remain in place.

At an eligible first-class K1 leaf, the candidate consumes the parent LP's scalar `G` only when its complete LP is terminal-valid, optimal, feasible, current-epoch, and attached to the same canonical interval/model SHA as the selected parent. The parent artifact's on-disk SHA is checked again before point selection. A finite, strictly interior binary64 `G` becomes `p`; missing, nonfinite, boundary or nonoptimal `G` falls back to the existing midpoint. No extra balance or endpoint-distance threshold is introduced. The candidate forms `[a,p]` and `[p,b]` from the same stored `p` and checks exact endpoint equality and strict interiority before the existing tolerance coverage check. A malformed geometry is an explicit failure.

The candidate still solves both complete child LPs before AM. The existing AM score and threshold `0.08`, depth `8`, minimum width `1e-4`, exact child infeasibility handling, terminal MIP, native-target requeue, atomic coverage transaction and one global deadline are unchanged. A proposed point or incomplete child pair is not a bound improvement; a deadline with missing child proof remains unknown. The fixed-point mathematics motivates this one point because it balances the *parent point's* two raw product-row violations. It does not promise an LP bound gain, exclude alternative optimal parent points, or predict MIP speed.

For candidate-only C6 lookahead reuse, the controller compares cached child id, parent, index, depth and exact proposed endpoints, then checks current LP/artifact epochs and domains, complete terminal LP status, recorded LP artifact SHA and the canonical model's on-disk SHA. A same-epoch old child geometry fails explicitly. A verified incumbent change is handled by the existing `ensureArtifact` invalidation, clearing parent LP/G/child cache; child artifacts rebuild through the existing path. The new candidate-only `round90_lp_g_split_choice.csv` in the external artifact directory writes binary64 precision 17, parent LP/artifact identity, raw G, midpoint, selected point/reason, child domains/cache verdict, both child LP identities/statuses, and separate proposal, child outcome, AM decision and realized transaction/requeue phases. The candidate-specific contraction ledger labels its actual split point and partition; default-off midpoint labels are preserved.

Pure geometry/cache source fixtures were added but **have only been compiled**. They cover exact closed union, fallback cases, adjacent representable interior G without a balance cutoff, invalid geometry, depth/width gates, and cache rejection after endpoint, epoch, LP-domain, SHA or completion changes. These pure fixtures cannot establish that a real native-target requeue triggers the controller check or that an incumbent update rebuilds both actual models; a later separately admitted actual-model qualification must observe parent LP → point → two child LPs, AM action, same-epoch requeue and epoch invalidation where reachable. No Round90 executable test or Optimize has run.
