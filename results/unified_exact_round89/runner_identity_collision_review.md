# Round89 G3 native callback evidence identity: bounded source review

Scope: current R83 ENS-C/C6 path, the conditional Round89 native-B1 runner, and the eight small Round88 ENS-C optimize ledgers. This is static/read-only review; no Round89 execution or runner edit.

## Finding

The runner's normal-return `len(summary)==partial+terminal` check is plausible for the active C6 path, but its requirement that every completed MIP summary's `model_sha256` still equal the **final** `external/models/<leaf_id>.lp` is not invariant. `runC6NativeTarget` increments a persistent per-leaf `c6_native_phase_count` and names each partial log `<leaf>_c6_<phase>_<kind>_target_mip` (`src/PaperExternalGiniTree.cpp:3825–3826,3870–3876`). A target-reached partial call can leave the leaf open and requeue it (`:4049–4088`), so multiple partial Optimize calls on one leaf are allowed. If that call also improves the verified incumbent, `incumbent_epoch` increments (`:3982–3993`). The next `ensureArtifact` on that open leaf invalidates the old model state and rebuilds using the tighter cutoff at the same path `models/<leaf_id>.lp` (`:3456–3483,3514–3517,3532–3534`). The old summary's SHA then correctly identifies the old MIP but cannot match the final leaf-path bytes. `scripts/round89_native_b1_g3.py:247–249` would reject a valid normal run.

The terminal log uses `<leaf>_terminal_mip` (`:8232–8237`). A terminal call with a valid optimal/infeasible outcome closes its leaf (`:8308–8314,8357–8382`); an interrupted call stops the whole run at the global deadline. Thus a second *normal* terminal Optimize for the same leaf is not seen on this active path. The `terminal_mip_started` guard (`:8181–8197`) resets on a model epoch (`:3479`), so filename uniqueness is not a general artifact-level guarantee if that lifecycle changes. The Round42 sibling-block and legacy C5 filenames are separate optional branches, not the active C6 leaf-target naming proof.

The eight Round88 ENS-C small ledgers (`results/unified_exact_round88/runner_a1_g3/raw/*_ENS-C/external/paper_optimize_ledger.csv`) have zero recorded artifact invalidations and at most one partial plus one terminal MIP per run. They therefore do **not** exhibit the collision; they also cannot justify a permanent-path invariant for Round89. The production optimize ledger already records per-call `model_sha256` and `native_log`; the new summary is written beside that native log (`src/GurobiBaseline.cpp:2770–2815`).

## Required runner correction before qualification

Keep the count and SHA audit. For each completed call, join the summary to exactly one optimize-ledger row using native-log path, solve kind, leaf id, and model SHA; reject duplicate/missing rows on normal return. Verify an immutable per-call model artifact if such bytes are retained. If only the mutable leaf path exists, explicitly record `source_model_bytes_not_retained_after_epoch` with ledger/summary SHA agreement and do not claim final-path byte verification of that older call. A stronger production fix would retain immutable model bytes keyed by call/model SHA. Do not silently discard old summaries or weaken `partial+terminal` count. Should terminal restarts become possible, use a monotonically unique call identifier in terminal native log and summary names.

## Historical P and source labels

`preregistration_g3.json`'s `historical_p_grb.source_round` values 83/85/87 and `canonical_sha256` are copied from the Round88 preregistration's `reference` fields (`scripts/round89_native_b1_g3.py:97–98`). They describe canonical P model ancestry. They are **not** the timing source: the contemporary Round88 P-GRB runs live under `results/unified_exact_round88/runner_a1_g3/raw/*_P-GRB`, used the Round88 A1 binary SHA `23d4fd53...42a54693` recorded in that preregistration, and remain an unpaired historical comparator only. The Round89 timed comparison is solely same-new-binary ENS-C versus native-B1. If citing Round88 P timing, bind the exact Round88 run receipts and label it historical/unpaired.

`source_commit_provisional` is an accurate preparation-stage label but becomes misleading after the qualification gate binds a final source. The runner currently asserts exact equality with `gate.source_commit` (`scripts/round89_native_b1_g3.py:113`), so a repaired source must update the preregistered value through a new reviewed revision; the label itself does not relax the hash gate.
