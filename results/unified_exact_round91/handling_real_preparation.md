D3 uses the actual LP travel coefficients, never the input's serialized distance matrix: the parser preferred its coordinate points.

For each vehicle let `a_k=Σ_j x_{k,0,j}` and `P_k=Σ_i p_{k,i}`. Source rows (`src/CplexBaseline.cpp:1493–1514,1521–1564,1724–1726,1800–1808`) give binary depot activation, depot return, F0 connectivity, pickup-to-visit links and `travel_k+cP_k≤T`. A used integer route may make extra visits and return loaded, yet its nonnegative directed travel is at least `ℓ_min=min_i(d*(0,i)+d*(i,0))`. The script audits those core rows and domains in the *actual parsed L0*; for each vehicle it reads every duration-row directed arc coefficient, treating an absent zero term as zero, then computes shortest paths with exact `Fraction.from_float` dyadic arithmetic. It rejects negative/nonfinite travel, nonpositive `c` or `q=(T−ℓ_min)/c`, and `B>2^53`. This fixed two-case probe does not implement the general `max(0,·)` inactive-route branch. Arm A adds nothing; B adds `P_k≤β_k a_k`, with `β_k` upward enclosed in binary64 from exact `q`; C adds `P_k≤⌊q⌋ a_k`, with integer coefficient exactly representable in binary64. Both added rows are read back before Optimize. C is a subset of B's relaxation because `a_k≥0`; the B-to-C difference isolates the integer floor from continuous travel/activation. Neither row asserts `P_k≤Q_k`.
