# Round 59：核心机制归因与 Gurobi 内部机制筛选

本轮以 Round58 研究提交 `edd65fe9f5bd37616366c1c6ca48379df062cdcf`
为基线，不以 main 为基线。新增行为全部默认关闭，稳定 preset 与问题语义不变。
逐项数字见 [结果表](result_tables.md)、[完整实例结果](full_instance_results.csv)
和 [内部机制配对](native_mechanism_pairs.csv)。结论只适用于这组代表面板。

## 研究合同、修正与局限

冻结 8 个开发与 2 个确认实例；确认集不参与候选选择。统一 Gurobi 13.0.2、
Threads=1、Seed=0、Presolve=Auto、MIPGap=MIPGapAbs=0，优化器串行。
正式 P-GRB 保持原 compact，不导入 HGA、路线、额外割或历史最优信息。
120 秒为端到端上限，正常收尾余量及实际原生工作时间另记。
未认证实例的过程耗时不是求解时间；不计算缺乏完整共同时间覆盖的 gap integral。
完整运行命令、二进制身份和进程预算均随报告提供。

以下实验身份问题在相应归因前纠正，已消耗运行全部计入预算：

* D4 首轮误用 T=2850；官方 P-GRB 指纹暴露应为历史原始 T=2400。
  四个错误场景运行被保留并隔离，四臂按正确参数重跑。没有混用两种 T。
* 旧 Round50 入口未继承当前 K1 的全部强化配置。六次 LP、三次 MIP 只保留为
  legacy-harness 诊断，不作为当前 F0 对照。新增研究入口后，D2/D3/D4 的初始
  canonical LP 与实际 K1-S 导出文件逐字节一致，再重新进行匹配试验。
* `strengthened=false` 仍保留连接流、cutoff 派生界和 F0 的 exhaustive-block
  移除。该组改名为“移除强化包的对照”，不再称原始 compact。最后增加真正
  原始 compact/F0 的两组同构建匹配；未受限原始模型先与官方 P-GRB 文件
  逐字节校验，恢复其原有 exhaustive-block 策略，再添加区间和 cutoff。
  为此取消可选 D2 窄区间及 D7 移除强化包运行，未扩大预算。

这也发现一个需要持续警惕的元数据问题：当前 `inactive families` 列表称
Gini spread、required movement 等关闭，但 paper-gf-tailored-bc 的继承配置
实际启用了相关行。研究以导出模型和回读为准，没有趁机修改稳定算法。
详见 [身份纠正](identity_correction.md) 与 [模型哈希](current_f0_identity.json)。

早期 D2/D3 的完整筛选与少量诊断编译发生 CPU 竞争，始终没有并发优化器。
因此这些墙钟数字仅作描述，不声称为干净的因果计时；预算优先用于正确的
当前模型实测，未再追加计时复测或长时扩展。后续修正 D4 与内部匹配试验
期间没有编译。Work、域、生命周期和证书另列，不能以 Work 代替端到端时间。

## 启动与外层：不能只减去 HGA 时间

K1-S 唯一的启动替换是独立验证空路线、Y=b；不是原生求解器的首次可行解，
也没有作为 MIP start 或 hints 输入。失败会显式中止，不偷偷运行 HGA。
Single-S 使用相同初始 U、完整 improving Gini 范围及当前 F0，取消外部分裂、
子 LP 探测和中间 native-target 暂停，仍支付一遍父 LP。
所有 Single-S 生命周期均检查至多一次 MIP、仅 L0，无子 LP。

开发集显示：

* D1 零目标：K1-H 约 1.55 秒中约 1.54 秒是 HGA；S 约 0.35 秒、Single
  约 0.31 秒，而 P-GRB 约 0.15 秒。去掉 HGA 有用，但不等于追平 plain。
* D2 正目标长 T：H 30.06 秒，其中启动 26.37 秒；S 7.46 秒，Single
  7.21 秒，P-GRB 9.56 秒。H 的初始 U=0.02254058，S 的 U=0.83659778；
  H 实际分裂 8 次并做 17 次 LP，S 不分裂。启动同时改变 cutoff 与几何。
  H 总时间减启动约 3.70 秒不能作为 S 的反事实时间。
* D3 major：H 的最终 gap 7.85%，S 14.43%、Single 14.82%，P-GRB 11.98%。
  H 保住更强 LB；S 找到更好的 UB=0.04500155，但证明较弱。HGA 并非只有
  成本，也改变了后续模型与搜索。H 两次 native 调用含短目标调用和终端求解，
  不能仅按调用次数断言重复搜索树。
* D4 正确 T=2400：H 启动只花 2.04 秒，却在预算末仍有 5.28% gap；
  S 90.26 秒、Single 90.05 秒认证，P-GRB gap 77.16%。H/S 均没有分裂。
  这是明确的非启动直接成本回退，不能归罪于 split 阈值；仍耦合 U、传播域、
  Gini 几何和原生搜索，没有进一步声称某一因素单独负责。
* D5：S 与 Single gap 都约 19.07%，H 28.55%，P-GRB 58.37%，说明强化
  算法在该优势例仍有价值；没有外部分裂的净证据。
* D6/D7：HGA 用完约 117 秒，未进入 LP/MIP，LB=0，末尾已验证 incumbent
  仍为空路线。S 恢复了证明工作，但其 gap 26.71%/70.97% 仍差于 P-GRB 的
  12.52%/62.39%。去掉启动后仍存在原生 primal/证明困难，不能宣称回退已修复。
  D7 的实际路线旅行时间可达约 11939 秒（P-GRB），确实覆盖长 T、长路线角色。
  进一步代码与阶段日志核查显示，两例 HGA 内部 fitness 都有进展，但达到
  work deadline 后，`HgaTgbcRunner.cpp` 显式跳过最终路线解码及独立验证。
  因而不能说 HGA 没找到有潜力的序列；只能说没有发布新的已验证 UB。
  内部 fitness 未被冒充可行目标，也没有用于固定状态 cutoff。
  这是 [启动验证交接证据](hga_handoff_audit.json)，本轮保持稳定行为不变。
* D8：四臂均认证，S/Single 约 1.57/1.54 秒，H 约 2.52 秒、P-GRB 约 2.06 秒。

S 在开发面板没有实际分裂。Single 去掉的主要是两次子 LP 探测及少量外层开销；
大多数终端搜索结果相同或很接近。本轮没有显示外层分解对 simple-start 的
净收益，但没有足够范围证明外层永远无用。H 的 D2 分裂是另一个初始状态，
不应与 S 的宽区间直接作结构因果比较。

## F0 与松弛表示

同 U、区间、cutoff 的当前模型根 LP **强化包移除对照**：D2 两臂都为 0.01922721，
D3 都为 0.02055001；D4 从 0.03992594 提高到 0.09394826。F0 不是普遍
提高根界，也不是普遍只有开销。单站整数域大小之和分别从 734→558、
435→348、413→214，不能把这些数相乘，也不能把域内取值当成已证明可路由。

D3 的 F0 根点所有 Y 已整数，但 G=0.01070626，按相同 Y 重算库存 Gini
为 0.03468468，最大 |zprod−G·Y|=0.57814。D4 对应 Gini 差约 0.04113。
路由、访问、操作变量也分数化；若无合法路线，库存向量本身不是原问题可行解。
这些是表示松弛的直接证据，但没有固定 Y 的路线可实现性求解来完整拆分两者。

原生根 cuts 后和非根节点另行采样。D3/D4 共八个代表点均未违反这组 pair
rows，必要访问条件过滤后每点只剩少量候选；仍不能推断全树无违反。
监测分别累计约 4.42/4.63 毫秒，四次读取均成功。D4 开关两次运行的节点与
Work 完全一致，时间 90.29→90.61 秒；差额不可全归于采样，也未作统计推断。
所有点均是原始坐标下的公开松弛值，不是实际 branching 决策、完整局部模型
或内部割池快照。

上述移除臂保留连接流，不能将其结果解释为原始 P-GRB。真正的原始 compact
同状态 MIP 配对另列。D2 窄区间可选试验已取消。
同上界的 HGA 耗尽诊断单列在结果表中，不冒充排除了 HGA
时间的完整算法运行。原生阶段证据包括 root/cut-pass、presolve 规模、
节点、迭代、Work、首次解、最终原生 UB 首次到达时间及其后的证明尾部。

## 机制 A：相同割集的静态行与原生池

采用全体 pair 的既有 support-duration 形式，使用非负有向最短路闭包证明
t(A) 下界。每个状态 198 条；生成一次，不在 callback 中枚举。两种执行
方式的 CSV 字节一致。所有行相对完整基模整数冗余，因此可以使用 Lazy=-1；
实际赋值与数量均回读成功，必要可行性行完全保留。
[数学说明](mathematical_notes.md) 给出全局有效性、必要违反条件和微型核对。

D3 同预算 F0 LB/UB=0.03862988/0.04500155，gap 14.16%；静态行
0.04069291/0.04500155，gap 9.57%，原生池 0.03756465/0.05660448，
gap 33.64%。静态行最终 UB 更早出现，节点数增至 20632 但 Work 下降，
说明节点数本身也不是成本指标。池根 Work 2.68→4.73，primal 也较差。

D4 F0 90.29 秒认证，静态行 93.77 秒，原生池 70.52 秒；Work 分别为
140.87、145.24、114.04。原生池约快 21.9%，静态行约慢 3.9%。
两种方式都呈混合表现，保留研究资格，均不升级主线。
Lazy=-1 成功不证明哪个割被激活或持续使用；运行差异包含 presolve、根处理
及后续搜索变化，不声称已识别某一条割的单独收益。
生成和池设置没有独立计时，包含在端到端与非原生阶段成本中；静态/池均
确定性生成并选择 198 行，全部添加成功，池属性全部回读为 -1。违反次数
来自独立采样点普查，不能当作求解器实际全树激活计数。

本轮贡献是可靠的下界适用范围证明与匹配执行证据，不是新 support-duration
不等式。也没有重开 Round52/53 的大枚举动态矩阵：该原生池路径不需要
PreCrush 或自定义动态分离；旧动态隔离结论只作为历史范围审计。

## 机制 B：有限原生搜索策略

统一测试一个 MIPFocus=1，保持默认 branching，不加 probing、starts 或 hints。
策略写入后回读校验。它不是数学贡献，也没有搜索参数网格或事后阈值。

D3 的 gap 从 14.16% 变为 15.88%，LB/UB=0.03811402/0.04530862，
最终原生 UB 首次出现由约 69.53 秒推迟到 111.28 秒。D4 从 90.29 秒
认证变为预算末 10.79% gap，LB=0.45171862、UB=0.50634331。
更低的根处理成本和每节点迭代数也未抵消证明损失。因此该原生策略不具备
本轮继续改进资格，没有再试 MIPFocus=3，也没有与割机制组合。
这不是对问题相关轻量启发式的否定：它没有构造或验证新的 BRP 路线。

在打开确认集之前，[筛选决策](screening_decision.json) 已冻结：没有选择
可统一推广的内部候选，两种割执行方式保留为 mixed，原生策略为负结果。
确认集只检查原先四个归因配置，不用确认结果挑选接口、参数或触发规则。

## 确认、同上界诊断与最终判定

真正原始 compact 的匹配对照以官方文件 SHA256 绑定来源，且两臂使用同一
新构建。D3 在相同 U、区间、cutoff 下，原始 compact 的 LB=0.04106142，
F0 为 0.03857343，UB 同为 0.04500155，gap 分别为 8.76% 和 14.28%。
这给出了一个无需启动或外层解释的 formulation 回退。不能把早先保留连接流
的移除包对照冒充这项结论。

D4 同构建配对则相反：原始 compact 预算末 LB=0.12867653、UB=0.50634331，
gap 74.59%；F0 在 92.58 秒认证。F0 Work=140.87，原始 compact 消耗
193.89 Work 仍未关闭。由此可说 F0 在该保护例有明确净贡献，不能因 major
的回退整体丢弃它。完整结果见 [原始模型配对](original_compact_f0_pairs.csv)。

D6 同上界 F0 的 gap 26.71%，移除包臂 15.92%；根处理约 23.31 对 15.42 秒，
平均迭代/节点约 988 对 435。强化增加的根与节点成本没有换来更好的终局界。
D7 同上界 F0 的总 Work≈284.33，全部记录在根处理阶段，约 116.93 秒，
最终 gap 70.94%，处理节点计数为 1；应把这里识别为根阶段停滞，而非深树
branching 已经探索充分。它们是受限状态诊断，完整 HGA 运行仍按真实超时保留。

确认 C1 四臂均未认证，同一 UB 下，P/H/S/Single 的 gap 分别为
27.06%/24.45%/25.34%/25.34%。确认 C2 也均未认证，gap 分别为
10.66%/7.30%/7.51%/6.83%；H 分裂一次，S 与 Single 不分裂。
这些结果支持保留 HGA 的研究价值，但没有给出统一默认替换的证据。

十例完整面板的认证数为 P-GRB=3、K1-H=3、K1-S=4、Single-S=4。
全部 40 个完整运行的返回路线通过独立 Python 重算；诊断证书没有混入此计数。
S 在十例中均无实际分裂，Single 的结果通常相近，C2 的终局界更好，major
则略差；本轮看不到外层对 simple-start 的系统性净收益，也不能由单次计时
差异证明外层无价值。H 的分裂收益仍与启动改变的几何耦合。

最终判定：

1. **HGA 值得作为可选强启动和对照保留**。major/C1 的下界表现说明它有价值；
   但允许启动耗尽全部工作预算、来不及验证发布候选的行为不适合统一筛选。
2. **Simple start 是有价值的研究配置**。它消除了大段启动成本，并在 D4
   多获一个完整证书；它仍可能损失下界，不是 P-GRB 的同义词，也未升级主线。
3. **F0 与外层分别判断**。F0 在 strong 的固定状态贡献显著，在 major 回退；
   simple-start 下的外层探测没有显示系统性收益，HGA 情况尚不能独立归因。
4. **内部机制没有统一赢家**。静态行和池分别有正负结果，保留为 mixed；
   MIPFocus=1 在两例都不优，不继续调参或组合。数学贡献限于有效性适用范围
   与执行证据，不宣称新不等式或新的求解框架。
5. **下一轮只优先做固定 F0 模型内的轻量 BRP 可行解注入**：从 simple-start
   出发，按受控原生事件调用小工作量的解码/修复，完整验证路线及变量映射后
   再提交，先不改区间几何。这能检验是否保留 HGA 的 primal 价值而避开长启动
   和几何回退。MIPFocus 的负结果不能代替这个问题相关机制的实测；也不能
   预先假定它能修复 G·Y 松弛或 V50 根停滞。major 与 strong 必须继续保护。

没有进行可选长时复测、D2 窄 HGA 状态、动态 callback 大矩阵或候选组合。
GRBcbsolution 的完整 BRP 注入链尚未实现；这是明确的下一轮范围，不是本轮
已经得到的收益。当前描述性 inactive-family 注册表仍有历史滞后，审计以
实际模型为准。本轮没有修改稳定 preset、合并 PR 或宣称全面泛化。

## 历史组件的重新判定

[组件状态表](component_audit.csv) 区分 API 支持、adapter 接入、preset、
运行时生效及历史范围；[历史追溯](history_attribution.md) 使用后续更正，
不将 Round55 epoch 修复前数字混作当前匹配基线。

* 原生 user-cut pool 以前没有接入，不能因旧 CPLEX 限制或动态 callback
  回退而提前否决；本轮已实际得到一正一负。
* support-duration 的根违反稀少不等于全树无用，也不等于静态行没有作用。
  但扩大穷举数量缺乏支持，动态提交成功不能当作割有效使用的证据。
* VD-P 的固定状态收益和完整 major 回退必须并存；惩罚 cover 的 live 测试
  当时没有开启，属于未测试，不属于负结果。
* inventory-route 全闭包的根提升未能抵消证明损失；不能由此排除未测试的
  一次性版本。也没有证据复活整个变量族优先级或 A1 探测矩阵。
* GRBcbsolution 在当前 Gurobi DLL 中存在，但 adapter 未加载/接入完整候选
  构造、映射与验证链。本轮用独立的有限原生策略诊断替代，不把接口可用
  冒充启发式已实测。未来候选必须先验证路线、库存、区间和 cutoff。

## 正确性与交付索引

空载出发、允许载车返回、单站单次服务、容量和原数学 T 均未改变；处理时间
为 (pickup+drop)×总 pickup，没有重复计费。C++ 独立验证器验证 native 解；
完整实例另用 Python 从原始输入与路线重算约束、最终库存和目标。
微型非度量有向图枚举覆盖载车返回；手算正目标 5/24 与 native 对照一致。
最终 Release 重建成功，36/36 项 CTest 回归通过（2.36 秒），包括新增的默认
关闭与非度量载车返回检查。原始 35 项回归也全部保留。
[验证摘要](validation_summary.json) 与 [测试日志](final_tests.log) 可复核。

共计账 80 次进程尝试，保守包含 3 次微型 native 正确性运行、1 次 CLI 失败
及所有被隔离的错误身份运行。不同性能场景共 11 个（10 个有效面板场景加
误设 T 的隔离场景），没有 1800/3600 秒运行；优化器无并发，外部 watchdog
没有触发。build-only 身份核查不调用优化器。最终性能结果已封存，不追加运行。
