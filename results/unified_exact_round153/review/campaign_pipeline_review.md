## Actual bound and model audit

`round153_read.floor_contract` locates the source by its actual model SHA and
parses the saved one-line LP grammar. The scope parser obtains G bounds,
objective cutoff, station supports, ratio coefficients and objective weights
from that matrix; it checks the hard resource rows, one-hot and state-G
rows, deviation rows, and state/Y bounds. The inherited per-call reader also
checks the saved true-G cap/floor rows and cutoff against the actual call.

For an accepted helper, the new reader verifies current-source scope and
identity agreement, beta=1 and the complete exact `d=h` map. It independently
recomputes the hard-total DP lower. For a qualified Native return it restores
the power-of-two objective scale, station constants, coefficient transport
and numerical guard, then takes the maximum with the DP lower. A zero-stock
branch, when present, is included by a minimum. Only status 2 or 8 can supply
a qualified online Native bound. An unsupported return retains the valid DP
positive-branch lower; it cannot delete that branch using unqualified
infeasibility. True returned stock values are re-evaluated independently.

The reader compares each emitted descendant with its own immediate base:
column order, explicit bounds, types and objective must be identical, and
the duplicate-preserving row Counter must differ by exactly the expected
original-objective floor row or by no row. Domain containment is checked in
the correct direction, with unchanged ratios/weights. An actually called
model must have the matching Native floor-row readback. The first formal
call is bound to the initial floor embedding by model SHA, not by a filename
heuristic. Formal models receive no inventory lambda or auxiliary column.

No inventory price upper becomes a routing upper. The formal endpoint is
still rebuilt from its own physical routes and qualified original-domain
cover. The new floor reaches that endpoint through an audited formal row
and normal Native proof observations, not by replacing the old endpoint
reader with the helper's result JSON.

## Frozen panel and corrected role adapter

The proposed eight positions are B/J pairs on N-B35-S, K-35-U,
R-B35-S-T1 and N-C20-U, respectively. Their prescribed windows are
2400 seconds for each difficult arm and 1200 for each N-C20 arm: 16800
seconds of nominal producer windows before verification reservations.
Every position has a fresh own-H destination, the same new PE, Seed 0 and
one thread. Only J receives the floor-helper arguments. Historical columns,
prices or another arm's incumbent are not injected into these commands.

The reviewer found and reported a real pre-freeze failure: the initial
`make_launch` asserted lambda=.15 for every role, but R137's R-B35-S-T1
uses lambda=`0.055125275219827186` and T=4800. The implemented repair keeps
each role's original lambda, verifies its argv/panel agreement and the
60-second pickup/drop parameters, and checks all roles before creating any
arm directory. The other three roles retain lambda=.15. This preserves the
frozen scientific roles and avoids a partially constructed matrix caused
by the incorrect assertion.

The reviewer requested explicit connections from internally consistent floor
metadata back to the frozen launch. These are now implemented:

- Match `meta.input_SHA`, B and Bminus to the launch panel and its actual
  input/resource totals.
- Match the emitted helper/manifest hashes to their frozen argv values and
  identity manifest hash, not only to each other.

The final source was reread: `floor_contract` now receives launch/identity,
checks both hash bindings, checks the actual input SHA and matches B/Bminus
to the panel's initial total and vehicle capacities. Its call site passes
the same frozen objects used by the inherited reader. These are pure
identity predicates; no new optimization or replay of the completed
own-root qualification is requested. The existing runtime handshake already
enforces the same identities in C++; the additions make the independent
reader's claimed own-source mapping explicit.
