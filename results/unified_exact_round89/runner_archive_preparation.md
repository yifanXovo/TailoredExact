# Round89 G3 raw archive preparation

This is source-only preparation while the rest runner owns the computation slot. No plan, source hash, compression, verification, test, build, or Optimize command has run. Existing Round88 archive kernel `scripts/round88_archive_evidence.py` remains unchanged.

The small driver `scripts/round89_archive_native_b1.py` reuses that kernel's source inventory, source SHA-256, tar/gzip creation, archive SHA-256, exclusive writes, and full streamed member SHA-256/size verification. It changes only the root to `results/unified_exact_round89` and derives the 16 planned arm identities from frozen `preregistration_g3.json`. It then derives the **attempted prefix** from the finalized summary and smoke/rest completion receipts, checking each row against the prepared launch and any top-level failure receipt. A normal 16-arm finish and an authorized early stop with fewer than 12 rest arms are both archivable; the latter needs a finalized rest completion with a stop reason. Every started arm with a raw directory is included, even if its solver/audit failed or its raw evidence is partial. Never-started arms appear explicitly as `not_run_arms`; a prelaunch failure with no raw directory appears as `absent_raw_attempts`, and an empty directory is also explicit. Unexpected, missing or ambiguously identified raw entries cause refusal. It archives **every existing file beneath each attempted nonempty raw arm once**; top-level runner identity, summary, stage completion, failure, risk-stop, lease, cross-arm and outer timing files remain separate small evidence for Git. Original raw directories are retained.

Only after the rest stage has halted, its completion receipt is finalized, all solver/build/heavy work has exited, and root explicitly grants an exclusive archive slot, run sequentially. Both commands check the active runner lock and process list before inventory:

```powershell
D:/msys64/ucrt64/bin/python.exe -B -u scripts/round89_archive_native_b1.py plan
D:/msys64/ucrt64/bin/python.exe -B -u scripts/round89_archive_native_b1.py build
```

The first command creates `runner_native_b1_raw_plan.json` with the attempted/not-run/absent/empty accounting, hashed top-level identity/summary/completion/failure receipts, and exact per-member paths/sizes and package grouping. Review that immutable plan before the second command. The build rechecks the whole inventory and those receipt hashes, then hashes each source file, writes each package with the frozen kernel, hashes the package, **reopens and streams every member**, and compares its SHA-256 and byte count with the original. The final `runner_native_b1_raw_index.json` contains the same attempt accounting, all member/source/package hashes and costs. Packages are grouped under `runner_native_b1_raw_archives/`, normally at most 36 MiB uncompressed source per part; an indivisible larger file gets its own part. Every compressed package must be **strictly below 45 MiB** or the build fails without deleting originals or silently retrying. An explicit failure receipt preserves the count of packages already completed.

Each of the two commands needs a separate **outer launch-to-exit wall-clock receipt** and stdout/stderr logs; the driver/kernel's nested phase times are explanatory and must not be added again. The external costs of both plan and build, plus any failure, are research/archive costs distinct from timed algorithm runs. A later root archive acceptance should compare the final index to archive SHA/size and all planned member paths, then list only the verified packages/index/plan and separate small runner metadata for Git. The existing runner's raw files must remain in place.
