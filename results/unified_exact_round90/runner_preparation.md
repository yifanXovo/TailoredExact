Candidate evidence comes from the new `round90_lp_g_split_choice.csv` writer, which flushes each proposal before child LPs and prints 17 significant digits. The audit checks the parent/children identities, strict finite interior split, exact shared endpoint, depth below 8, chosen point equal to the parent LP's raw G (or exactly the legacy midpoint computed as `lower + (upper - lower) * 0.5` with a stated fallback), current incumbent/artifact/LP epoch and SHA, parent and child LP Optimize/status receipts, C6 and finite-child adaptive-mass decision ledgers, and realized tree event or ordered same-parent native-target receipt. It labels retained canonical model bytes as SHA-verified current bytes; if a later epoch overwrote the file, the historical point is linked to its original Optimize SHA and its old bytes are marked unavailable. A final overwrite without a subsequent Optimize remains explicitly unverified rather than rejected or represented as archived old bytes. A forced whole-run kill is `partial_unknown_after_interruption`, never zero splits or a fabricated complete proof. A graceful native global deadline may return after a proposal, child LP pair, or AM proposal without a realized transaction; that phase is recorded as unknown with original parent coverage retained, not mistaken for a completed split. No proposal, or only midpoint fallback, is recorded as **nonexposure** to LP-G point behavior; if smoke is nonexposure, observation can continue only to the first already registered next role under root's stage gate. Rare epoch/cache branches can remain unobserved and are not replaced by extra toy solves.

The candidate ledger is emitted only with the Round90 flag. A normal candidate run with LP Optimize calls but no ledger, a control arm with such a ledger, a missing/ambiguous model receipt, an epoch mismatch, an invalid child partition, or an unsupported realized action fails audit and stops the batch. The new audit is source-only and still needs syntax/helper qualification against the final writer and at least one actual ledger-bearing run before any performance conclusion. A normal run with `complete_pair` but no realized split may correctly proceed through exact parent closure; the audit records that AM action rather than inventing a split. The raw G field is written directly from the parent's stored LP result; its epoch/model linkage is checked, while no independent exported primal-G file is claimed.
