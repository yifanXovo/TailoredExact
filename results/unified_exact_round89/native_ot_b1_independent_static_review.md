**Initial snapshot verdict: not ready for executable qualification.** The interval arithmetic runtime guard and independent rounded-product oracle needed correction first. Later sections record the targeted repairs and final verdict.

The intended validity argument is sound *conditional on genuine outward arithmetic*. The audit requires `Y_i−Σγ_iy state_i_y=0`, `r_i−α_iY_i=0`, one-hot selectors, and both `h_ij≥±(r_i−r_j)` rows, all with exact imported binary64 coefficients. At an integer solution one selector per station equals one, so `r_i=γ_iyα_i` as an exact real product of the two imported coefficients. A nominal binary64 knot β with enclosing product interval incurs at most its station's maximum support error. Any chosen CDF sign row on the nominal supports is bounded by their pairwise absolute distance. Triangle inequality then gives the B1 row with `δ_model`; coefficient enclosure plus one-hot gives `δ_coeff`. The submitted RHS and activity interval must be outward, and a reliable submitted violation must exceed the unchanged read-back `FeasibilityTol`. Arbitrary signs at a numerically perturbed callback point remain globally integer-valid. This does not claim rational `y/D_i` equality, original-model LP validity, or callback cut persistence.

Findings:

1. `NativeOtB1.cpp:60–65` tests `denorm_min()*1.0 == denorm_min()` as a constant expression. An optimizing compiler can fold it, so the check cannot establish the run-time FTZ/DAZ state that the `nextafter` enclosures assume. Use an actual runtime floating operation with observable operands/result (or platform control-register validation with a portable fallback); reject unsafe arithmetic before preparing or submitting any row. A pure microtest should exercise this guard where possible, without altering solver tolerances.
2. `round89_native_ot_b1_fraction_oracle.py` only audits `γ={0,1,2}` with `α=fl(1/3),fl(1/7)`. Multiplication by two is exact binary exponent scaling, while the C++ `roundedProduct` adds an artificial one-ULP interval even for exact products. Thus a positive reported support-error allowance does not prove the actual two-link rounding case. Add a small independent `Fraction.from_float` suite with γ=3 or 5 and a genuinely unequal exact product/β, both CDF sign orientations, coincident and adjacent nominal knots, and finite/nonfinite safety boundaries. Enumerate the integer pairs and check the *submitted binary64* coefficients/RHS, not only an ideal symbolic row.
3. `findRow` scans every imported row for every required row; `matchesRow` copies its `std::map` argument on every probe. For D7's ~104,726 rows and ~1,225 station pairs, the two h rows alone imply about 256 million row probes, charged against the global proof deadline. Build a one-time row index by an expected participating column (the h column is particularly selective) and compare exact sense/RHS/terms by const reference, still rejecting missing or duplicate matches. This is an implementation-cost issue, not a mathematical cut counterexample.
4. On callback or summary-write failure, `GurobiBaseline.cpp:3672–3680` invalidates final bound/incumbent eligibility and `solver_finalization_reached`; the paper controller's engineering gate then rejects that solve. However `native_bound_events` remains populated, and `PaperExternalGiniTree.cpp:7221–7242,8289–8310` writes its events to global trace *before* that gate. Clear failed events or gate trace emission so a failed Round89 call cannot leave entries labeled as valid native bounds. The current final-certificate stop is present; the issue concerns intermediate evidence.

The production callback is restricted to terminal and partial-target MIPs, checks optimal MIPNODE status before reading `MIPNODE_REL`, submits all reliably violated pair rows with per-callback h deduplication, and records `GRBcbcut` return 0 as API success only. `PreCrush=1` is set/read only on active candidates; the ordinary LP path is inactive. No new node, row, Work, or internal time cap was found in the Round89 path. The requested whole-call deadline includes audit setup. The direct toy's off/static/callback and production backend's LP/terminal/partial arms are structurally appropriate, but none has run.

`main.cpp:11155` gives the tailored diagnostic a local R83-looking preset when Round89 is selected. Its result is overwritten by `applyRunConfigSnapshot(buildRunConfigSnapshot(...))` at `main.cpp:19858`, and the normal Round89 ENS-C solve follows the gcap-frontier path; this line does not by itself lose final result identity. Qualification should still check the final JSON identity and full method activation for each actual arm.
