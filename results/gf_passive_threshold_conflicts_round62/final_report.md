## 1. 被动 archive：合法条件、实测收益和成本

保存两个上界：`U_control` 用于原模型及外层控制，`U_archive` 来自固定 PREFIX 的完整、独立验证见证。被动模式不将 archive 写入 start、hint、native Cutoff、模型行、传播域、叶子顺序、切分评分、续解目标、控制 incumbent 或 epoch。旧 `OUTER` 仍在原生调用后合并 archive，`SUBMIT` 还会向原生提交候选；本轮没有把这两种行为重命名为被动，也没有重开其调参矩阵。

Single-S 的完整模型覆盖 `0≤G≤min(U_control,(n−1)/n)`、`F≤U_control`，因 `F≥G` 而覆盖所有严格改进解。结合原问题控制见证，其 native bound 可转换为 `min(U_control,B)`。K1 使用完整叶子快照：包括尚未求解、进行中、关闭及空叶；只有覆盖合法替代的祖先才被排除。当前整个叶子的 native bound 与该叶旧界取最大，再对所有有效叶取最小并以控制上界封顶。检查实际覆盖区间、模型身份、cutoff、epoch、界与见证一致性。

仅在 `min(U_control,U_archive)−L_global≤1e−7` 时，CERT 可调用合法 `GRBterminate` 或在外层边界停止。返回后再次检查完整 ledger、最终界、原始路线、数值质量和生命周期；native `INTERRUPTED` 不改写为 `OPTIMAL`。观察模式只观察，不触发提前停止；即使没有 native incumbent，也不妨碍有合法外部见证的完整认证。证据文件持久化与已验证内存 archive 分开标记。

同一合法逻辑进度下，usable UB 和绝对 gap 不劣是数学结论；计入 PREFIX 和观察成本后的墙钟不增加则不是。

## 2. 阈值推广排除什么，松弛实际改变什么

单站最多一次非零单向服务，使 `P_i≥q ⇔ Y_i≤b_i−q`、`Drop_i≥q ⇔ Y_i≥b_i+q` 成立。旅行下界使用非负有向图最短路，而不是对任意输入套用直达欧氏距离。若同一车服务两个事件，其时长至少为两站访问旅行下界加 `c·max(要求取车总量,要求送车总量)`。空载出发使总取车量不小于总送车量；允许其他供应点、接收点及带载回仓都不破坏这个下界。容量约束作用于服务量及每个载荷前缀，不能把整条路线总取车量限制为一车 Q。

按实际 Q 向量、单站时长和数量计算保守的可选车辆集合；不同站事件两两不相容时，同时成立的事件必须使用不同车辆，因此事件计数不超过其可选车辆并集大小。每次减小阈值都重验全部边和并集，禁止复用过期车辆资格。当前输入只支持共同 T，没有虚构异构时限接口。

统一生成规则为每站每方向至多一个最大可行数量种子（至多 2V），按固定顺序搜索；最多 50,000 搜索节点、64 个初始 clique、4,096 次弱化验证、32 个最终冲突。共享字典、去重与同支持上的阈值支配都固定，不按实例名称、历史最优值或确认表现分支。正式输入不包含历史库存或路线。

D3/D4 生成约 0.006 s。长时限角色没有边，降低相同方向阈值只会减弱时间下界并扩大车辆资格，因此不反复枚举这一路径；这不证明更大集合旅行/资源条件无效，本轮没有将其冒充已测机制。

D4 手工回归 `P1≥5, Drop2≥1, Drop3≥6, Drop6≥6` 的六条下界为 2407.05293、2566.68417、2477.53809、2804.00998、2728.52790、2463.83372，均超过 `2400+0.024`。三辆车不能同时满足四个事件，对应 `Y1≥20 或 Y2≤6 或 Y3≤12 或 Y6≤7`。四个坐标上的禁止 box 包含 `20×30×25×14=210000` 种整数组合，其余站点仍自由；旧四坐标精确 bit no-good 只排除其中一个坐标组合。该数字不是可行路线数，也不是廉价投影实际排除点数。正式生成器输出了不同的首个自动冲突，未硬编码这个回归例。

初始六种 D4 表示的 plain LP 目标都为 0.09394825539；D3 的 OFF/库存投影/RLT 都为 0.02055001075。对没有已有值的新事件使用合法连续补全，未任意选 z 宣称违反。记录的 OFF 根处理及代表节点也未被这些行分离。

本轮没有增加阈值专用域传播器。固定模型的生成成本、原生根处理、Work、节点及有限点违反度分别记录在数据附录和 `native_point_separation.json`；没有把 native 内部预处理或传播变化单独归因为新行的收益。

随后执行的包含关系实验改变了“可能已经全被原模型隐含”的判断：逐条在 OFF LP 内最小化库存投影左端，D3 有 20/32 条、D4 有 4/32 条找到违反点，最大违反度为 0.625 和 0.35。每批最多 33 次 LP 调用，共用 120 s 进程 cap，实际总进程为 0.781/0.547 s。保存点经独立旧模型逐行及域检查，最大旧行残差小于 1.4e−12。这是数值支持的严格可行域缩小，发生在原目标最优点之外；不等于提高目标 LP 下界，也不能断言这些点就是原生速度变化的原因。

额外推导说明了表示差异。自动 DFS 在第一次出现车辆缺额时保留 clique，弱化后仍有 `|C|=|K(C)|+1`。令每个库存投影项为非负 t，合法标量事件最小值为 `max(0,1−t)`。于是 clique 可连续补全当且仅当 `Σt≥1`，即库存投影恰为该标量 LP 表示在原变量上的投影；这不适用于任意更大缺额的手工 clique，也不保证相同 MIP 搜索。

预案外又推导并实现服务量投影：取车项为 `(A_i−P_i)/(A_i−q+1)`，送车项为 `(B_i−Drop_i)/(B_i−q+1)`，和至少为 1，其中 A/B 为合法单站取送上限。至少一个事件为假即证明整数有效性。库存平衡表明库存项等于服务项再加相反方向数量的非负项，故服务投影支配库存投影；在现有 F0 单站 perspective 服务域下，它也可由服务耦合事件+缺额一 clique 消元得到。

但服务投影重新优化的目标 LP 仍等于 OFF。v3 D4 同构建三臂为 OFF 90.109 s、库存投影 55.359 s、服务投影 78.344 s，均认证。更强行比 OFF 快，却比库存投影慢 22.985 s，未通过事先冻结的替换保护门槛。D3 的无干扰同构建比较为 OFF 315.110 s、服务投影 307.422 s，均认证，Work 为 523.266/523.592，时间差未达双门槛。不使用受 Git 自动维护干扰的第 54 次记录归因。

v3 D4 服务投影的实际增量为 0 列、32 行、384 非零元，仍无新变量，但比库存投影多 256 个非零元。服务投影没有损失这两个 OFF 固定区间证书，D3 的本次保护对照也没有出现大幅回退；它与 v2 完整 Single-S 库存投影的差异不是同构建、同生命周期的严格速度配对。它相对 D4 库存投影的回退使事先冻结的替换门槛失败。故不调整门槛追认胜者，保留服务投影的有限正负信息；完整 K1/确认继续使用库存投影作为混合结果研究参照，而不是合格主线候选。没有对未进入完整 K1 的服务投影宣称端到端优势。

与历史族的区别是数量阈值和车辆分配矛盾，而非重新命名 support-duration、inventory-route 或全库存 VD-P。原有 pair/triple 行保留；历史根点无活动并不构成删除它们的依据。没有重跑旧大面板或用旧构建时间作新配对。也没有声称这些基础 clique、析取或乘积 lifting 是新颖数学。

## 5. Oracle、预算与证据边界

自动首个 D4 冲突（取车站 1/2/3/4，阈值 1/4/4/11）可直接由廉价条件判定，进程 0.078 s，内部证明约 0.002177 s，无 optimizer。对同一阈值条件强制 native oracle，在同构建 v2 用 64.828 s，得到 `T_LB=2407.052930515325`、验证的 `T_UB=2407.05293075613`，native OPTIMAL，优质数值残差。这证明该阈值模式不满足原 T=2400；不是 F 的下界，更不是原问题最优证书。所有其他站点继续允许供给/接收，原 T 派生的删弧、域和 Big-M 已释放为安全时长模型。

oracle 支持阈值判定：界可靠超过 T+裕量或有验证路线不超过 T 即可结束，跨越 T 保持未知。本次强制 native 例最终为 OPTIMAL，没有测到重型 oracle 提前中断的额外性能收益。廉价证明可替代这一个模式的重型判定并跨原库存状态/合法 Gini 叶复用；不能推论所有昂贵库存缩减都已被替代。最后构建加强了 oracle 日志、停止请求和数值质量门；v2 成本对照独立保留，不冒充最终日志构建的时间。

预算、全部启动、内部调用和失败资格见 [budget.json](budget.json)、[processes.jsonl](processes.jsonl)、[runs.csv](runs.csv)、[pairs.csv](pairs.csv) 与 [完整数据附录](data_appendix.md)。第 49 次旧构建 K1 OFF 正常结束，之后旧队列在下一实验启动前被明确暂停，保留为未配对记录。第 54 次遇 Git 自动维护，保留计费及物理见证，排除性能归因并用最后预留做同构建重跑。没有拼接 fresh 扩展、隐藏查询、剔除负结果或放宽证书容差。

实际为 **72/72 次计费启动、199 次内部优化器调用**：4 个纯证明批次、12 个 LP、50 个固定区间/完整算法性能进程、2 个 native micro、2 个 oracle 对照、2 个 LP 包含关系批次。600 s 预算启动 26 次，120 s 40 次，20 s 6 次；总计费进程墙钟约 14529.56 s。全部完成，无失败、watchdog、超预算或未知调用计数；54 仍排除性能归因，57 为其干净重跑。

## 6. 哪些已证明、哪些实测、哪些仍未知

- **数学合同：** 完整覆盖下的外部 UB/LB 认证；被动 UB 在同进度不劣；服务事件的整数等价；有向旅行/处理量下界；车辆并集 clique；每次弱化重验；库存及服务投影有效性、后者支配关系；缺额一时的连续消元；Gini lifting 的区间作用域。
- **有限实测：** D3 三臂的有限非干预轨迹；D1 外层与 native micro 真停止；D7/D6 的 usable UB 收益；D3/C2 的 A 长窗证书保留；自动阈值冲突；原 LP 区域确有可分离点但目标 LP 不升；D4 表示差异；C2 完整 K1 的 B 证书增益；C1 时间收益，以及 D3 时间和 C3 gap 回退。稳定 K1-H 参照没有被新机制按冻结时间双门槛显著超过。
- **未建立：** 非平凡困难角色的外部提前认证收益；所有输入上的墙钟非劣；长 T 的更大集合资源机制；服务投影或 RLT 的普遍 MIP 优势；跨机器、Gurobi 版本或更大面板的主线资格。未使用的机制不写成已测负结果。

本轮阶段性提升在于可真实停止的被动认证、比精确库存点更大的可复核条件冲突、对表示 LP 投影关系的解释，以及超出冻结最优点的包含关系实测。预案外 B3 的 Gini RLT 没有增益；B4 的包含关系检验排除了“所有行均被 F0 隐含”的解释；B5 的服务投影在数学上更强，但 D4 相对库存投影退化，未通过替换门槛。由观察到的弱点提出替代机制，再按同构建对照停止不合格分支，构成本轮实际探索过程。
