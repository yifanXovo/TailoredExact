# 持续研究目标：形成更适合这类 BRP 的统一、论文友好的精确算法

你负责在本地 C++ 项目 `yifanXovo/TailoredExact` 中持续开展研究、实现、测试、分析和再优化，在每个实质性阶段验收后提交一个可审查的 draft PR。继续使用 Gurobi 作为完整 MIP engine；不要求从 LP engine 重写搜索框架，也不要求保留 K1 的既定架构。

**整体目标是：找到并验证一个更适合本项目 BRP 的统一精确算法，以原始 P-GRB 为主要 benchmark，在不同规模、不同类型的实例上形成稳定优势，修复 K1-AM 相对 P-GRB 的重要回退，并基本保留其已有的重要优势。**不是围绕 K1 完成一轮变体测试，也不是要求新算法逐实例超过 K1 或所有历史研究配置。

“更适合”不要求每个组件全新，也不要求为求不同而推翻 K1。可以保留、组合、替换或简化有依据的已有机制；最后形成明确的方法、贡献说明和完整证据。性能价值、实现修正和理论新颖性分别判断，不把它们相互冒充。

本任务替代此前以内部秒数/Work 分配、信用补充和定时暂停恢复为核心的后续预案。历史实现和数据仍有研究价值，但旧 prompt 要求过某机制，不等于它符合本任务的正式算法准入条件。

## 1. 研究目标与比较关系

| 比较对象 | 要回答的问题 |
|---|---|
| 官方 P-GRB | 新算法是否达到主要性能目标？ |
| 字面 K1-AM，以及明确定义的可靠性修正版 | 是否修复原有回退、基本保留重要优势？ |
| 固定状态、消融和历史研究变体 | 具体组件产生了什么作用？ |

新算法可以在部分实例上比 K1-AM 稍慢或 gap 略差，只要相对 P-GRB 仍有实质优势、主要既有优势没有丢失，并在其他关键角色上解决了旧缺陷。不能再使用“任何一点比 K1 差一定比例”或“必须保留每个历史变体的单点最快纪录”作为自动否决条件。

同时，不得为了修复小实例而破坏中大实例优势。原来 K1 明显胜过 P-GRB 的重要角色，如果新算法变成明显落后于 P-GRB，或虽勉强领先却损失了大部分实质优势，应作为严重问题分析。比较须同时看相对 P-GRB 的位置与相对 K1 的损失，而不是只看一个比例。

目标至少包括：

1. 修复历史证据确认的若干小规模严重回退，尤其是不能由 HGA 直接耗时或零目标终止浪费解释的回退。小实例足够接近时允许归为无实质差异；没有依据时不能把所有差异称为随机误差。
2. 修复 CitiBike 实验中的重要回退，分别处理启动、原生可行解搜索和非零目标证明困难；零目标停止不能代替这些问题的解决。
3. 在 CitiBike 及其他代表性中大实例上建立相对 P-GRB 的稳定优势。先核对哪些角色、在哪些共同预算下确实由 P-GRB 胜出，再针对真实问题研究，不凭印象建立目标。
4. 基本保留 K1 的重要优势，最终给出统一算法和统一参数规则，不向用户提供需要逐例选择的最佳配置表作为最终方案。

这些是研发目标和有限证据范围内的验收要求，不是对所有未来实例的运行时间支配定理。未经确认的短窗波动不自动否决一个方向；反复证实的关键中大实例重大劣势，也不能被均值或其他实例的巨大收益掩盖。

## 2. 正式算法的准入条件

### 2.1 正确性、设计依据、效率证据分开

每个主要机制说明三层依据：

- **正确性**：为什么不改变所求原问题的最优值，不遗漏必要解或证明范围？新模型、割、传播、分解和证书的作用域是什么？
- **设计依据**：利用了什么 BRP 特性或明确的数学代理？为何采用该决策？参数有什么意义？
- **效率证据**：对完整认证时间、共同预算下的合法 UB/LB/gap 和端到端成本有什么影响？

不要求每个启发式 gate 都有“保证运行更快”的定理。AM 的父子界代理、归一化经验阈值、初始区间数等可以研究和修改；需要数学含义及实验支持，而不是将经验参数称为理论最优。反过来，证明某机制不会破坏精确性，也不等于证明它适合加进算法。

模型重构应说明原问题变量上的解与目标对应。**并非所有合法优化都必须保留每一个原可行赋值**：对称性破除、支配删减等可以去掉等价或不必保留的方案，但必须证明对所有适用输入和当前区间/cutoff 范围无损保留最优性。它们不能冒充“对全部原可行解都成立”的有效不等式。保留若干已知最优见证只是测试，不是等价性或无损性的证明。

数值容差下的认证、解析有效性证明和严格有理证书分别描述；不得因设置零 MIP gap 就声称完成了未经实现的严格有理验证。

### 2.2 允许的设计自由度

允许修改或放弃 AM，改变切分点、初始区间数和 gate；区分域排除与继续细分；不分解、使用单 MIP；重构或替换内层 formulation；设计问题特定 cuts、传播、搜索引导、可行解构造及 Gurobi API 交互；也允许其他有依据的精确架构。

统一算法不等于每个实例走完全相同的路径。依据容量、数学时限 T、库存域、服务量、路线结构、有效 LP 界等当前问题信息决策是允许的。规则、参数含义与适用范围必须统一；不能按历史结果设置个别例外。

固定逻辑迭代数、候选数或邻域规模不自动禁止，但要解释其算法/复杂度作用，并保持参数数量克制。不能只是把内部秒数预算改名为另一种运行资源计数。允许合理随机化，主实验固定并记录随机设置；不挑选最有利 seed，也不把 seed 当作实例类别。

Gurobi 原生默认内部策略不需要重写或移除。本任务限制的是你额外设计、作为方法组成部分的干预规则。新 API 机制先核对官方接口和实际接入情况，不能假定有并不存在的自定义分支、局部割或续解能力；通用调参网格不能作为主要贡献。

### 2.3 禁止将运行资源截断作为正式算法的主要决策

正式候选不得采用：

- 按实例名、文件 ID、历史胜负、已知最优值或事后规模阈值切换模式。
- 规定某个 LP/MIP/证明服务运行 k 秒、k Work 后放弃、转向或重试；依据 CPU 时间、Work 速率、机器性能或剩余时间比例分配数学子任务。
- 将上述机制改称信用、时间片、资源门、恢复或兜底后继续使用。
- 将多个完整算法的逐例最好结果拼成一个新算法，或隐藏并行、重复搜索、重建及外部启发式成本。
- 根据确认结果添加专用关闭条件，或改变原问题、benchmark、可行性/证书容差来获得优势。

这不禁止**由有效数学证据触发**的停止、剪枝、域收缩、分裂或模型重建。例如达到合法证明目标、证明一段范围不可行后转向下一段，可以研究；必须保持覆盖、计入成本并解释状态变化。若研究多模块协同，也必须是一份统一方法，不能变成按运行资源切片的完整算法组合。

**实验截止不是内部算法策略。**可以给一次完整运行设置共同的 3600/7200 秒截止，向内部调用传递同一全局剩余期限，并在到期时结束整次运行、保存合法结果。不能以此为名另给组件分配时间片，然后继续执行其他分支。独立诊断子问题可以有限时，其未知结果只用于研究分析，不直接成为正式算法的时间驱动选择规则。

异常保护、资源不足和数值拒绝需要安全处理并报告；不能在正常运行中借它们实现隐藏选型。已有不符合条件的预算设施保留为诊断，不自动继承到新候选。实验运行是否继续受整体资源管理约束，与正式算法如何解一个实例是两件事。

## 4. 原问题、基准和证书合同

保留原 BRP 目标，记目标库存为 $D_i$：

$$
Y_i=b_i+\sum_k(d_{ki}-p_{ki}),\qquad r_i=Y_i/D_i,
$$

$$
S=\sum_i r_i,\qquad H=\sum_{i<j}|r_i-r_j|,\qquad
F(Y)=\frac{H}{nS}+\lambda\sum_i\omega_i|r_i-1|.
$$

沿用实际站点集合、$S=0$ 处理、权重解析、单站单次非零单向服务、空载出发和允许带载回仓的全部原始语义。车辆容量限制载荷前缀，不限制累计 pickup；按当前取卸约定，实际支持共同 T 的输入满足

$$
\operatorname{travel}(R_k)
+(c_{\rm pick}+c_{\rm drop})\sum_i p_{ki}\le T.
$$

若实际接口支持其他合法情形，核对后明确表达，不为套公式虚构输入能力。不得强制所有车辆空载回仓、错误保持站点总库存不变、重复计算操作时间或硬编码面板参数。

官方 P-GRB 始终为原始 compact 模型和原生默认启发式，无新增启动、cuts、历史路线或其他算法界。主要比较沿用并回读当前合同：同机器和 Gurobi 版本、Threads=1、Seed=0、Presolve=Auto、原要求的 gap 与数值标准。新机制必需的设置差异单独说明，不能削弱 benchmark；若升级版本或修复底层行为，相关参照同步重新绑定，不能拼接旧时间作严格配对。

保留字面 K1-AM，并明确 K1-H、K1-AM 等名称对应的实际 preset。可以设仅整合合法候选保存、零目标及时停止的可靠性修正版；在候选与该修正版的配对中，不重复计算同一项修复的收益。它有端到端价值，但不是新的非零 MIP 证明贡献。

原始路线—操作见证验证后才是正式 UB；有效全域下界和完整覆盖才形成原问题证书。固定库存、辅助不可行点、受限区间证书和中断 LP 的 primal ObjVal 不能冒充全局证明。不同表示的模型哈希可以不同；需要检查的是明确、正确的数学与实验关系，不强行要求新旧等价模型字节相同。

## 5. 宏观优化方向：供选择，不作为完成清单

根据真实缺陷选择最有价值的主要假说，深入到可运行实现与完整比较。以下方向可以组合或放弃，不要求逐项做完，也不要求一个阶段同时打开全部方向。

### A. 重新选择分解组织

比较完整单 MIP、当前分解和有数学依据的新策略。允许修改 AM，区分合法域收缩与继续递归探测；不要为了保留原方法名称而强制 split。

在同初始见证和同合法信息条件下，比较直接求父域与分裂后处理全部必要子域的累计成本，包含探测、建模、状态传递、串行求解和实际剪枝。LP 可以辅助近似 MIP，但其改善不代替完整净收益。实验标签可以来自运行时间，正式 gate 不能直接由内部时间/Work 截断执行。

### B. 重构或替换内层表达

研究节点载荷、逐弧流、Big-M、库存编码、Gini 产品等是否存在可替换的弱连接或重复表达。先证明合法关系，再比较松弛、规模和原生总成本。过去“保留旧块再叠加新块”的回退，不自动否定无损替换；变量少、根界强也不自动保证更快。

### C. 处理库存与路线可实现性的关键耦合

目标由最终库存决定，库存是否能由车辆、访问顺序、载荷和时限实现是另一层困难。可以研究有效不等式、域传播、联合子结构、分解或证明复用，明确排除的是什么点/区域以及对证明目标有什么影响。

已有阈值、累计时间、共享资源、投影和 oracle 可复用，但不要求全部进入新算法。低库存目标不是合法路线；只在短 T 上成功不能宣称解决长路线；不预设必须使用重型 oracle 或完整 Benders。

### D. 利用 Gurobi 的问题特定机制

允许有依据的 cut 执行、MIP starts、hints、分支引导和轻量可行解构造。核对真实接口与历史实验范围，不把成功提交视为实际采用或性能收益，不把旧接口障碍当成永久否决。

启动成本、初始 U、派生域、原生提交和外层行为分开分析。可以采用少量必要消融，但不反复展开无信息的大矩阵。新颖性声明针对性核对相关原始文献；不把一般流模型、通用剪枝或常见启发式复用自动称为新理论。

你也可提出未列出的方向。优先选择能修复真实 P-GRB 回退并形成统一方法的机制，而不是只选择最容易出现局部正结果的角色。

## 6. 自主多阶段研究闭环

一个阶段应围绕一个主要假说或紧密相关的机制，包含实际实现、测试和足以影响下一步的结论。每阶段执行：

1. **立项与准入**：说明目标缺陷、结构依据、历史差异、参数、必要对照和本阶段资源计划。先排除架构不合格设计，不先花大量计算验证再讨论能否采用。
2. **实现与核验**：完成真实运行路径和必要测试，隔离默认开关，核对实际模型及设置。明显数学错误先修复或弃用，不继续无意义性能测量。
3. **筛选与解释**：用少量代表点寻找有区分力的证据；局部改善检查代价，局部回退分析原因，不能立即添加实例特判或否定整类未测机制。
4. **修订或转向**：按证据改进、简化、替换。连续阶段都没有修复目标缺陷时，重新审查核心表示/分解选择，而不是无限微调同一参数。
5. **阶段验收与 PR**：检查可信度、论文友好性和目标进展，提交独立 draft PR，记录正负结果及下一步。
6. **整体判断**：未达到最终目标且仍有授权资源时，继续下一阶段；完成一次 PR、若干尝试或一组积极实验不是整个任务完成。

不预设必须经历多少阶段，也不要求每阶段都有性能正提升。每阶段至少应有明确的增量成果或有价值的否定证据；不要用日志修正、空接口或微型测试充当完整优化阶段。

**持续研究不等于无限运行或保证一定找到满足全部目标的算法。**区分“最终目标达成”“阶段完成但整体未达成”“真实资源/环境/会话限制下暂停”。在可用授权资源内主动继续，不因为一轮负结果就停；接近真实限制时保存状态并如实说明，不能无限消耗资源、虚报达标或承诺不存在的后台续跑。恢复条件具备后按索引继续，不要求用户重新设计每个实验。

## 7. 分层测试与资源管理

每阶段先声明拟测角色、配置、调用/批次数量和单次最长预算，运行中维护累计次数及实际计算成本。没有统一的“72次完成即结束”配额，但也不能将未规定总次数解释为无限计算授权。资源计划决定要开展哪些实验，不进入正式算法的内部选型逻辑。

### 7.1 开发与回退诊断

可从约8–12个结构有区分力的开发/保护场景组织研究，不要求每阶段全跑。覆盖规模、容量/车队、库存类型、地理结构、数学 T、零/非零目标，以及 primal/证明困难；避免大量近重复样本替代结构覆盖。

普通诊断先用120–300秒，必要时到600秒，结合现有模型和调用证据。涉及认证尾部或短长窗口排序反转时，再做600–1800秒等适当匹配验证。小实例若本来几秒结束，无须人为用满预算。已有可信证据能回答的问题不重复长跑。

### 7.2 有潜力候选的中大实例比较

不要求全部收敛。候选通过基本正确性、准入和小面板筛选后，选择有决定性价值的中大角色，以共同3600秒预算比较候选、官方 P-GRB 和必要 K1 参照；少数困难角色可延长到7200秒。7200不是每个探索臂的默认配置，也不是没有潜力时继续等待的理由。

复用同一次长运行中的有效检查点，报告早中晚轨迹。已认证正常结束；新启动的延长对照标为 fresh run，不能拼接几次运行冒充一次。不同上限下各自的终态不能直接比较，优先使用双方实际记录的共同时间点。

不能为修复原问题而修改数学 T、V、Q或库存数据。微型简化和反事实实例可以用于验证结构，必须与原性能实例分开。

### 7.3 完整成本、复测与污染控制

端到端计入启发式、建模、预处理、分离、全部必要子问题、重建、验证和收尾。默认单线程、串行优化器，不与编译/重型审计争用 CPU；如研究其他资源配置，另立公平比较，不混入主表。

阶段计时用于归因，不能从正式总时间里扣去 HGA 或失败探测。固定见证、同区间和去组件实验只作清楚标注的诊断；正式算法自行取得其使用的信息。

微小差异、异常波动、证书恰跨预算边界和关键大幅改善，按需要做有限复测。结果可称“差异较小”而非未经检验的“统计等价”。不需要对每个候选跑庞大多 seed 网格，也不能挑最好 seed 报告。

## 8. 绩效口径、确认与整体结束条件

### 8.1 冻结的是判断口径，不是必然获胜的结论

在相关候选结果开放前，明确“相近、明显改善、严重回退”的实用标准，同时考虑绝对与相对幅度。可按预先说明的规模/难度组设合理口径，但不能在看到结果后更换门槛或利用分组掩盖失败。这些标准属于实验评价，不是正式算法参数，也不自动等于统计显著性。

- 双方认证：比较完整认证耗时及原证书标准；小例接近可以接受。
- 共同预算内未认证：报告合法 UB、全局 LB、绝对 gap、统一定义的相对 gap及重要轨迹。零目标、无有限 UB、无合格 LB单列，不任意填为0%或100%。
- 若 LB 超过 UB 超出原容差，先处理证据/数值问题，不能静默裁剪为零 gap。接近零的目标不要用比例制造夸大改善。
- 不要求 UB和LB每项都优于 P-GRB。上界与下界一优一劣时说明原因与影响；若仅靠一个 gap 数字无法形成清楚结论，标为混合或未定，补充有价值的窗口/指标，而不是强行排名。更好UB的贡献不能写成更强下界。
- P-GRB已认证而候选未认证是重要负结果；结合共同预算和尾部证据判断程度。K1的对应证书损失也需分析，但不自动等于相对P-GRB失败或整类机制被否决。
- 根界、节点、Work、变量数和割数用于解释，不代替最终比较，也不重新成为被禁止的资源切换规则。

汇总胜率、耗时比或性能曲线时，同时展示主要回退集合、中大实例、类型分组及未解情况。不得只统计双方均解出的一小部分而隐藏大量未解/丢证实例，也不能用少数巨大零目标节省抵消重要非零回退。

### 8.2 确认与防止反复适配

在候选、参数和执行规则冻结后使用未参与该次设计的确认数据。确认须覆盖目标问题族，至少包含非零目标/证明困难的中大角色；机械完成两个已公开近重复实例不等于充分泛化证据。关联的地理样本或同一基础实例派生参数要说明，避免将高度相关场景当作完全独立验证。

可以用历史公开但未参与本阶段选择的角色作确认，准确标注，不能称全新封存样本。确认用于修订后即转为开发数据；修订版需另有未参与该次选择的检验。预算或数据不足时说明泛化资格尚未建立，不换掉不利结果、降低结论要求或继续称原确认独立。

### 8.3 整体目标达成的条件

依据预先明确、覆盖主要缺陷和优势的验收范围，至少确认：

1. 方法正确、架构论文友好，最终算法和参数规则可以统一清楚地写出。
2. 已核实的主要小实例/CitiBike严重回退得到实质修复，不能只有零目标等待修正。
3. 目标中大实例和不同类型上形成相对P-GRB的稳定优势，关键已确认的大幅劣势没有被平均数掩盖。
4. 基本保留K1的重要优势，允许合理局部取舍，不要求逐点超过K1，但不接受广泛重大损失。
5. 完整算法及拟宣称有效的机制实际运行，确认范围和结论相称，没有只靠固定LP、微型实例或未触发开关达标。

达标声明限定于已完成的证据范围，不声称所有未来输入上普遍更快。若仍有预定关键问题未解决，报告阶段进展并继续研究或在真实限制下暂停，不能把目标事后改为“有几个点变好就完成”。

## 9. 每阶段验收与可审查 PR

阶段验收保持简洁，回答三个问题：

**结果可信吗？**检查原问题、配置、实际生效路径、独立见证、合法界/覆盖、数值和成本。退出码零、文件存在或单元测试数量不能替代完整验证。无效运行隔离，错误及修复前后身份保留。

**架构合格吗？**以一份简洁伪代码检查统一性、参数意义、证明范围、内部资源策略、实例选择、状态变化和未计费工作。确认失败后才添加的例外不能通过。实现与描述不一致时先解决，不用文字包装。

**对最终目标贡献什么？**分别说明相对P-GRB、K1及消融的结果，修复了哪些缺陷、牺牲了什么、哪些仍未知。性能负结果不等于证据无效；架构不合格也可以作为失败研究记录，但不得作为下一候选的默认启用组件。

验收是对本阶段证据与结论的审查，**不要求每个阶段性能都通过最终门槛才允许提交 PR**。可信负结果、被否决方案或正确性问题的发现可以交付，需明确状态；不能将存在未披露错误的方案标为合格候选。

每个实质性阶段提交一个新的 draft PR，明确基线提交、增量及下一步。微小编译/日志修正不必各建 PR；完整优化阶段也不应长期只留本地，等所有研究结束才统一提交。阶段 PR 是保存进展，不是整体目标结束。

每阶段在明确的研究基线上建立分支。允许清楚的堆叠 PR，也允许从更早干净基线分出替代方案；说明依赖，防止下一阶段静默继承不合格机制。失败实现可保留为默认关闭设施或独立分支，历史证据不删除。

不向 main 重复提交累计历史，不改写旧 PR，不自动合并或覆盖稳定默认。每阶段保留精简的 `final_report.md`、实际算法/参数定义、必要数学说明、输入/模型/构建身份、机器可读运行与配对结果、关键见证、失败记录、资源汇总和复现入口。
