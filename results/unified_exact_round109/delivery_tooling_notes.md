# Delivery tooling record boundaries

Native, reader, diagnostic, qualification, packaging and restored-public execution failures retain their actual source/command/streams/exit/receipt records in the carrier or direct supplements. This note discloses lower-level interactive delivery checks whose original record is the Codex tool transcript rather than an independently captured execution directory. Their uncaptured wall time is unknown; no retroactive receipt is invented.

- Initial selective Git staging omitted `--sparse`. `git add -f --pathspec-from-file=results/unified_exact_round109/delivery_stage_initial01.txt` refused new result paths outside the sparse checkout, after staging the permitted script/reference paths. The enclosing inline Python call raised `CalledProcessError` with return1. The actual tool transcript preserves that command and refusal; it was retried successfully with `git add --sparse -f --pathspec-from-file=...`. No raw, model, source5, candidate, performance or threshold changed.
- `git diff --cached --check` initially returned1 solely for original blank lines at EOF in preserved stderr streams and the independently audited parser/source copy. Those bytes were preserved. Related path-specific `.gitattributes` exemptions match the existing historical approach; the final check passes. This is byte-preservation metadata, not a scientific or source repair.
- A read-only `Get-Content` probe looked for an independent wrapper's `stderr.log` before locating its actual `stderr.txt`. The tool transcript records the missing-path error. It wrote no evidence and launched no solver; the actual operation receipts remain authoritative.
- A read-only inline PR-body metadata check initially decoded `gh` UTF-8 JSON using the UCRT runtime's GBK default and raised `UnicodeDecodeError` before writing metadata. Its actual command/error remain in the tool transcript, with uncaptured wall time unknown. The corrected check parses the original JSON bytes as UTF-8 and reads the source body explicitly as UTF-8. No PR-body, scientific data or configuration was changed by this decoding correction.
- A multi-file delivery-document `apply_patch` context check initially used `Measure` where the actual line was `Measured`, and failed before applying any edit. Its source/error are in the tool transcript; the corrected context applied normally. No raw or scientific file was involved.

The failed first public pack and superseded normal second pack have their real execution directories and repair/inventory records. They are separate from these interactive tooling checks. The final public carrier and restored mathematical validation were unchanged by Git staging or whitespace metadata.
