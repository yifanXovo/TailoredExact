# Bounded Round162 recovery

This delivery separates measured C++/PE identity, recorded scientific evidence,
the fixed Git science snapshot, and later publication metadata. The full goal,
research section, reports, decision, qualified matrices/duals/routes, failed
receipts and relevant measured source bytes are new Round162 evidence. Old
inputs/provenance are pinned by commit/member/SHA in the input and history
manifests; no whole historical archive or old producer is needed for the
bounded recovery check.

`public_manifest.json` hashes exact staged Git bytes, excluding itself to avoid
self-reference. `carrier_manifest.json` lists split ZIPs and compressed member
indexes. Each index binds every new member by path, length and SHA256. Source
and snapshot bytes are separately hashed so checkout line-ending conversion
cannot masquerade as a measured source identity. No PE, commercial DLL,
license, credential or protected dirty-file inventory is published.

After the normal science push, `round162_delivery.py restore SCIENCE_COMMIT`
downloads this round's manifest and listed files anonymously from that fixed
GitHub commit, then checks every new ZIP member against its index. The restore
root is under `E:/codes/ExactEBRP-work/restore/round162_public_*`. It downloads
no old carrier, compiles nothing and invokes no Optimize. Its exact scope is
byte/member recovery, not an independent mathematical or Windows performance
rerun. Publication I/O has its own receipt and is not a new solver sample.

The measured development PE is bound by `measured_manifest.json`, with changed
source snapshots v3--v6. Early v1/v2 prototype hashes and failures are retained;
some early prototype source bytes were not retained, and no exact rebuild of
those prototypes is claimed. The complete six-arm PE is bound by
`complete_candidate_manifest.json`: stable complete_v2, source e920b92e199e,
Gurobi 13.0.2 DLL SHA256
`9b5fccef82043cc9a0f052d31fa9c12b6d59cec999ad0cc19ca1b68ed6d18a88`.
All six actual Windows processes have live PE/DLL path observations in the
carrier. Original scripts/flags and object/archive hashes are retained.

The complete build's source inventory also lists unused translation units.
The post-science default-build repair adds the missing namespace brace to
`Round160PhysicalNeighborhoodStub.cpp`. That no-Gurobi stub was excluded from
the measured Gurobi PE; `engineering/default_stub_fix.json` binds the old/new
bytes and failed build fee. The performance PE and all compiled performance
inputs remain fixed. The clean no-Gurobi and Gurobi/research builds are
engineering checks, not additional performance samples.

A new Windows solve requires the separately installed commercial runtime and
the documented GNU toolchain. The original manifests and launch records use
absolute local Windows paths; adapting those paths is required on another
machine. The absent public binaries are not advertised as directly executable
reproduction. Pure saved-matrix/dual/fleet readback uses Python; the actual
complete verifier's bytes at review time are retained separately. A later
default-stub inventory exception changes no numerical verification arithmetic.

Six complete arms were started, not ten. Matrix positions 7--10 contain only
predeclared launch identities. `complete_small_role_decision.json` applies the
permitted adverse-primary-role stop before those producers existed. Do not
run them merely to fill a table or spend the remaining budget. Any resumption
must first inspect original PID/birth/fee/producer seals to avoid duplicate work.

Scientific costs are actual outer fees, including failed solves and required
verification. Nested Source, H/helper Runtime/Work and Native callbacks are
already included, not summed twice. Extra post-panel per-arm readback time is
included in derived T_verify/T_total, with original sealed closeout values
preserved. A shared review setup is a round-level verification fee.
The first PC qualification's conservative T_verify includes reader-repair idle
time and has no performance eligibility. Compilation and public recovery I/O
are separately reported. Historical main benchmark CSVs are unchanged.
