# A2 固定路线网络数量 oracle：独立数学审查（2026-09-26）

**结论。** 网络是一个成立的、严格受固定车辆分配和站点顺序限制的整数数量子问题；线性成本的负残量环证书、正 `S` 处的梯度及 primitive 整数线段推导正确。作为通用 oracle 必须显式约束删站旅行；当前 ENS-C/A1 的 CLI 已有带容差的 metric 前置检查，仍须最终物理验证。零服务时间与时间容差的边界也要明确。`S=0` 时确定性返回 `no_gradient_at_zero`、保留已验证原解，足以定义此**启发式**，但不表示数量邻域耗尽。线性 oracle 最优绝不等于原目标 `F` 最优。

## 源码假设与网络投影

`include/Instance.hpp` 的 `Q、capacity、initial、target` 均为整数，`pickup_time、drop_time、dist` 为 double；`src/Parser.cpp` 在点坐标完整时重建欧氏距离，否则直接读序列化矩阵，本身不检查 metric。**但** `src/main.cpp:19653–19668` 对包含 `research-round83-vds-equal-net-exchange` 的强化预设调用 `src/PaperK1AmSf.cpp:7–31` 的 `hasMetricTravelLowerBounds`：检查对称、对角和三角不等式，使用 `1e−9` 量级的相对容差；A1 继承 R83 预设也受此守门。`src/CplexBaseline.cpp` 的 `Σ_k z_ki≤1`（约 1584–1587 行）、单车 depot 起终与访问流（约 1490–1514 行）、`p_ki≤min(b_i,Q_k)`、`d_ki≤min(C_i−b_i,Q_k)` 及互斥 mode（约 1720–1751 行）、负载/返库非负与 `travel+(c_p+c_d)Σp≤T`（约 1756–1808 行）对应固定路线。`src/Evaluator.cpp` 从零负载出发，允许载货返库，按 `c_p P+c_d D+c_d L_end=(c_p+c_d)P` 计服务，采用 `duration≤T+1e−7`，并拒绝零操作、同站重访。`src/Round75QuantityDescent.cpp` 的旧邻域只枚举一个站的整数改量或两个站反向等量改量，并在变零时删除站点。

对每车访问序列 `i_1,…,i_m`，令 `u_i=p_i−d_i=b_i−Y_i`、`L_j=Σ_{h≤j}u_{i_h}`。所提弧守恒令首站前 `L_0=0`，中间/末弧流分别为 `L_j`，故 `0≤L_j≤Q_k`，末站至 `t` 允许 `L_m>0`。`s→v_k` 容量 `K_k` 给 `Σp_i≤K_k`，`t→s` 的 `Σ_i b_i` 容量不额外收紧，因为各 pickup 弧已受 `b_i` 限制。`p_i≤b_i`、`d_i≤C_i−b_i` 保证库存界。对于整数流，在同站同时正取送时减去 `min(p_i,d_i)`，保持 `u、Y、L` 和任何线性库存成本；取送总量与服务时间不增。取消后非零 `|u_i|≤Q_k` 自动由两侧负载界推出，满足 compact 模型的单站车容量上界。反向地，任一**完整固定模板**、零初载、整数取送、前缀可行且 `Σp_i≤K_k` 的数量方案按这些弧分配，恰得整数循环流。含删站后旅行节省才可行的原路线不在这个限制集合内。

上段到**实际删站路线物理可行**还需每个被跳过片段的有向三角不等式，或逐候选直接计算新旅行并拒绝超时者。非 metric 反例：`0→A→B→0` 旅行 `1+1+1=3`，但 `0→B=10、B→0=1`；令 `b_A=b_B=1、Q=2、c_p=c_d=0、T=3`。现有 `A` 取 1、`B` 取 1 可行，网络候选 `A` 变零而 `B` 取 1 在完整模板旅行 3 下可行，删 `A` 后旅行 11，物理不可行。这个矩阵会被当前 ENS-C 前置检查拒绝，但说明独立调用 oracle 或迁到其他方法时不能省略 metric 输入合同。ENS 的数值三角容差沿多个跳点可累积，故即使通过守门，仍须逐路线原 `verifySolution`。

当 `c_p+c_d>0`，数学上 `K_k=floor((T_k−travel_k)/(c_p+c_d))`；实际验收有 `1e−7` 容差，直接 floor 只能描述名义 `T` 限制，不能声称覆盖所有 verifier 可行解。例如 `travel=0、c_p+c_d=1、T=1−5e−8`，物理验收允许一次 pickup，名义 floor 却为 0。保守缩小 `K` 对启发式安全，但须先核**当前路线也在网络域内**，否则零成本起点、线段可行证明失效。`c_p+c_d=0` 时 `Σ_i b_i` 是有限 pickup 上界，但必须先检查完整模板旅行本身 `≤T`（或声明采用原验证容差）；否则一个过时模板也被纳入。空车路线与异构 `Q_k` 分别用零流、逐车弧容量处理；初始库存/站容量弧不可省。

## 线性 oracle、梯度和线段

弧成本 pickup `−g_i`、drop `+g_i` 总和为 `Σg_i(d_i−p_i)=Σg_i(Y_i−b_i)`，与 `Σg_i(Y_i−Y_i^current)` 只差常数。整数容量、整数起始流和整数瓶颈增广保整数性；若残量图无负成本环，则任意另一可行循环流之差分解成残量环，故是**此网络的线性目标**最优。有限有界整数流与严格负成本增广保证数学终止，不给实现运行时间上界。若 `λ、w` 来自 double，可按其实际二进制值精确有理化成本；这不替代最后的原 double 目标验收。

在 `S=Σr_i>0`，`H=Σ_{i<j}|r_i−r_j|` 时，`∂H/∂Y_i=Σ_{j≠i}sign(r_i−r_j)/D_i`、`∂S/∂Y_i=1/D_i`，商法则正给提案的 `g_i=[SΣsign−H]/(nS²D_i)+λw_i sign(r_i−1)/D_i`。相等比值/目标处取 0 是一致的配对反对称次梯度选择，但可能错过有限整数改善，不能推断局部最优。若所有非负库存为零，则 `S=H=0`、源码规定 `G=0`；沿 `(ε,0)` 等正方向 `G` 可保持非零常数，故连续延拓不成立、不可求该梯度。`no_gradient_at_zero` 安全保留原状态；还需让日志明确不是 exhaustive 终止。

目标处 tie 的具体风险：一车按 `0→1→2→3→0` 走上述共线 `0.1,0.2,0.3` 位置，旅行 `0.6`，`T=6.6、c_p=c_d=1/2`；`b=(2,3,3)、C=(6,3,7)、D=(2,3,4)、Q=4、λ=2`。当前 `u=(1,1,−1)`、`r=(1/2,2/3,1)`、`F=71/39`。在第三站 `r_3=1` 取 penalty 次梯度 0 后，`g_3=10/169>0`；54 个网络可行整数状态中，唯一线性 oracle 解 `u^*=(0,0,3)` 的 `F=7/3` 更差，primitive 差的 gcd 为 1，整条 line search 无改善。但合法零操作状态 `u=(0,0,0)` 的 `F=37/66` 更优。它证明“此 oracle/线段没有改善”并非完整数量邻域或原目标的最优性证书；零操作站可按 metric 删去。

若 oracle 库存与当前相同，应返回 `no_direction`，不可对 gcd 0 作除法。否则 `d=(Y^*−Y^0)/gcd_i|Y_i^*−Y_i^0|` 为整数 primitive 方向，`t=0,…,gcd` 的库存、净操作和每个负载前缀在端点间仿射，故保持整数与上下界。每车 gross pickup `Σ max(b_i−Y_i(t),0)` 是凸函数，端点均 `≤K_k` 即全段 `≤K_k`；完整模板的服务界成立。删零站后的时间仍依赖上述 metric 条件或逐点物理验收。`a2_line_search_proposal.md` 的折点/驻点邻近整数定理可用于这条一维线，但需处理 `S=0`、零操作删站、精确边界舍入和严格 `F` 复核。若按确定性原目标严格下降接受，有限库存/访问模板状态保证数学上不循环；数值实现应记录已验值与截止时间，不能用线性 oracle 最优冒充 `F` 最优。

## 真正超出 Round75 的微型见证

以下是独立精确有理枚举，不是 D6 性能证据。单车顺序 `0→1→2→3→0`，站点位于一直线上距 depot `0.1,0.2,0.3`，完整旅行 `0.6`；`Q=3、T=3.6、c_p=c_d=1/2`。令初存 `b=(4,1,4)`、容量 `C=(4,4,6)`、目标 `D=(3,3,1)`、全权重 1、`λ=2`。当前净取量 `u=(1,−1,2)`，前缀负载 `(1,0,2)`、pickup 3、库存 `Y=(3,2,2)`、`F=32/11`。固定模板及允许删零站的整数数量状态共 40 个；其中 Round75 型单站或双站反向等量邻居仅 8 个，最优邻居 `u=(1,0,2)` 的 `F=11/3>32/11`。当前梯度恰为 `(-8/363,−272/363,256/121)`；网络线性 oracle 的唯一最优是 `u^*=(0,0,3)`，库存 `(4,1,1)`，gcd 为 1，原目标 `F=9/4<32/11`，返库载量 3。删前两站后的旅行仍为 0.6，物理可行。故该联合三站方向**确实可能**突破已耗尽的 single/pair 邻域；还没有任何真实多实例耗时或改善证据。

可重现的无求解器精确枚举为 `a2_network_quantity_fixture.py`（SHA256 `6d4f980fbb6abe909d67bfb28ee43d1927e7c0a67496f6c598a8a8d549f076bc`），实际输出 `a2_network_quantity_fixture_output.json`（SHA256 `990ba72517160da7de4cba611fe0d538bf5e65553ff594eb73ed4ff1cfb55bda`）。脚本枚举 175 个库存界整数净操作，核对网络与删站后物理可行集合完全相同，恰得 40 个、8 个旧邻居、唯一线性 oracle 解与上述各精确分数；仅使用 Python 标准库 `Fraction`，没有调用求解器。

复核协调者修订后的 `a2_network_quantity_proposal.md`：现已明确当前点必须属于名义预算域、`c_p+c_d=0` 仍须完整模板时间可行、`S=0` 和 gcd 0 的确定性保留，以及 ENS-C 的 metric CLI 守门；数学主张与上述限定一致。提案中“handling plus loaded-return cost is ... times the cancelled total pickups”宜将 *cancelled total pickups* 改为 *remaining total pickups after cancellation*，避免把被取消量误读为实际服务量。
