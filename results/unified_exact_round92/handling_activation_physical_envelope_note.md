# Round92 uniform physical/canonical envelope: repair contract, not an implementation

**Status.** The existing Round92 row is proved for the serialized canonical duration model but is not uniformly valid for the original physical route set. G1's zero-Optimize LP identity PASS remains true; native G2 and performance G3 must stay closed until a repaired row and its evidence are separately reviewed. This note proposes one uniform proof construction, not a parameter choice, extra cut family, code change or run authorization.

## Exact counterexample and source of the gap

`Instance` stores `total_time_limit`, `pickup_time`, `drop_time` and `dist` as `double` (`include/Instance.hpp:24–28`); CLI parses real-valued times with `std::stod` (`src/main.cpp:775,1445–1446`). `Evaluator.cpp:62,112–119` uses those raw coefficients and accepts `duration <= T+1e-7`. The compact writer first sums `cunit=pickup_time+drop_time` and `writeExpr` prints a coefficient within `1e-12` of one as exactly one (`src/CplexBaseline.cpp:215–250,444–450,1870–1895`). The Round92 helper currently builds its shortest-path/handling proof from those **emitted** coefficients.

Let `δ=2^-42`, all directed travel zero, two stations, one vehicle with `Q=2`, initial/capacity `(2,1)`, positive targets and weights `(1,1)`, `T=2−δ`, and `pickup_time=drop_time=(1−δ)/2`. A route `0→1→0` picking 2 at station 1 starts empty and returns with load 2. The exact raw physical duration, and here also the binary64 evaluator's duration, is `2(pickup_time+drop_time)=2−2δ<T`; station 2 remains stocked, so the objective denominator is positive. All these coefficients are exactly representable dyadics; zero travel satisfies the ENS-C metric guard. The writer emits `c=1` because `|1−δ−1|<1e−12`; the canonical duration constraint at that route is **`cP=1·2=2>T`**. The current Round92 proof uses `ell=0` and `B=floor((2−δ)/1)=1`, excluding the physically feasible `P=2,a=1`. The old canonical duration row also excludes this route. Thus the new row is valid for the old canonical integer feasible set, but canonical validity alone does not imply original-physical validity. The pre-existing writer normalization itself prevents a blanket original-problem relaxation claim on arbitrary permitted real input.

## One lower coefficient system and one Floyd pass

For every **actual** directed x-column arc `(i,j)`, let `d_raw[i,j]` be the raw `Instance::dist` binary64 value treated as an exact dyadic, and `d_can[i,j]` its parsed canonical duration-row coefficient. Define `d_low[i,j]=min(d_raw[i,j],d_can[i,j])`. Keep the same arc-presence bits, including emitted-zero arcs; reject a missing/mismatched support or any negative/nonfinite input. Let `c_raw=pickup_time+drop_time` as the **exact sum of the two stored binary64 values**, not the rounded `cunit`; obtain a proved downward enclosure `c_raw_lo<=c_raw`. Let `c_can` be the actual parsed service coefficient and `c_low=min(c_raw_lo,c_can)`. Nonnegative inputs make every lower coefficient nonnegative. The current original duration row and all original tolerances remain untouched. If `c_low=0`, time implies no finite uniform positive handling bound, so record the valid no-row outcome.

Run the same directed shortest-path enclosure **once** on `d_low`. Its minimum depot-to-station-to-depot lower endpoint `ell_low` is a lower bound on the travel of every depot-closed route visiting a station, for both raw physical and canonical coefficients. This needs no triangle inequality; nonnegative directed arcs, exact x-column support, one active depot tour and F0/service links suffice. The original mathematical physical time and canonical duration are each at least `ell_low+c_low P`. Consequently one upper horizon `H` covering both time domains gives the valid integer row

`P_k <= B a_k,    B=max(0, floor(q_hi)),    q_hi >= (H−ell_low)/c_low`.

Use outward upper subtraction/division on exact stored dyadics, and require finite exactly representable integer `B` (the existing `B<=2^53` guard). If there is no depot-closed station path, F0 and service links imply `P=0`; a `B=0` row is valid. A negative numerator also gives `B=0` **only when the certified quotient upper endpoint has floor at most zero**; a wider outward enclosure may yield a weaker positive `B` and remains safe. Lower/upper quotient floors agreeing is telemetry, not an instance selector. On the dyadic counterexample, the physical lower `c_low<=1−δ` and the horizon below give `B>=2`, so the physical route is retained. This construction is valid on the union of raw-exact physical and emitted-canonical integer tours, subject to the numerical-acceptance bound next.

## Covering the actual Evaluator acceptance rule

Simply replacing `T` by `T+1e-7` is insufficient: the evaluator accumulates travel and computes three products, two service sums and the final duration sum in binary64. A uniformly conservative bound can be obtained without a new tolerance or adjustable parameter. Share the evaluator's **same binary64** `1e-7` constant with the proof helper (for example through one named header constant, with unchanged value); copying an unrelated literal creates avoidable identity drift. Let `u=2^-53`, `rho=1−u`, and `eta=2^-1074` (one minimum positive subnormal). Require actual binary64 evaluation of each operation (`FLT_EVAL_METHOD==0` or an equivalent verified toolchain contract), round-to-nearest IEEE arithmetic, gradual underflow, no fast-math/reassociation and finite nonnegative intermediates. Then every addition or product used here satisfies `fl(z) >= rho*z−eta` for exact nonnegative `z`. If excess precision or double rounding is possible, this particular `u` proof must not be reused unaltered. The helper and physical verifier must maintain the safe floating environment through the run; reject a changed rounding mode, FTZ/DAZ, nonfinite values or unsupported evaluation semantics. The existing model-build runtime guards are a starting point, not a substitute for that continuing contract.

For an original-feasible **single route per vehicle**, station uniqueness gives at most `m=V+1` evaluated travel arcs. Its load starts at zero; if `P` pickups, `D` station drops and `U` returned load, exact conservation gives `D+U=P`. `int` counts convert exactly to binary64 when within their normal checked range. Repeated use of the preceding one-operation bound yields

`travel_fl >= rho^m travel_raw − m eta`,

`service_fl >= rho^3 [pickup_time*P + drop_time*(D+U)] − 5 eta`,

`duration_fl >= rho^N duration_raw − (V+7) eta,    N=max(V+2,4)`.

The service expression matches `Evaluator.cpp:112–115`: three rounded products followed by two rounded sums. The last inequality adds the final rounded travel-plus-service sum and uses `m<=V+1`; all terms are nonnegative. Let `tau` be the shared binary64 physical feasibility tolerance. Compute `H_cmp_hi` as a certified binary64 upper enclosure of the exact dyadic `T+tau`; it covers the evaluator's comparison RHS whether that addition is rounded or temporarily held at wider precision. If the evaluator accepts a route, `duration_fl<=H_cmp_hi`, hence its exact raw duration satisfies

`duration_raw <= H_phys := (H_cmp_hi+(V+7)eta)/rho^N`.

Compute an outward binary64 **upper** enclosure of `H_phys` (for example add `(V+7)*eta` outward, then divide upward by exact `rho`, `N` times). Use `H=max(T,H_phys_upper)` in the one quotient above. This also covers an exact canonical duration feasible at `T`. Do not round `eta` to zero; `(V+7)*eta` is an exact positive subnormal while its checked integer multiplier is small enough, or an exact dyadic implementation may be used. Any overflow, unsafe FP mode, count overflow or unrepresentable resulting bound fails the candidate before Optimize; it does not silently switch off the row or alter the original tolerance. The additional horizon may weaken the row, which must be measured anew rather than inheriting the old C2 LP gain.

The `Evaluator` currently checks station repetition and physical load/duration but does not itself reject two distinct `RoutePlan` objects bearing the same vehicle index. The one-tour-per-vehicle mathematical problem and canonical F0 model do not permit that representation. A proof claiming validity for **every verifier-accepted vector of RoutePlan** needs an explicit one-route-per-vehicle witness check; otherwise limit this lemma to the intended one-tour domain and do not cite `Verification::feasible` alone as that stronger premise. Checked bounds on `P`, `D` and `U` must also prevent signed-`int` overflow in `Evaluator`; no floating proof legitimizes undefined integer arithmetic.

## Identity, qualification and exit boundary

Use one versioned run-local proof key binding the raw and emitted directed arc values/presence, raw pickup **and** drop doubles, emitted service coefficient, `T`, station count, checked operation-count bound, the shared tolerance's bit pattern and the evaluator arithmetic contract. G interval and incumbent epoch do not alter this physical proof and need not enter the key. The candidate ledger should expose `c_low`, travel lower-bound source, `ell_low`, `H_phys_upper`, `B`, exact-floor/uncertainty status, cache hit/cost, and every source identity; retain the canonical model SHA as before. The lowest-cost focused qualification retains the existing G1 off/on/readback checks and the dyadic counterexample above, independently verifying that the repaired row admits `P=2` while a separately chosen ordinary instance still produces a nontrivial row. This is a proof-and-identity gate, not a new performance experiment. Neither G2 nor G3 should start until it passes and root separately admits them.

## Minimal implementation refinement: lawful counts and opt-in witness admission

The lemma applies to the intended domain: at most one depot tour for each vehicle, each station visited at most once globally, a valid node/operation on every stop, nonnegative integral pickup/drop, load in `[0,Q_k]`, and inventory in `[0,capacity_i]`. On one lawful tour every operation magnitude is at most `Q_k`, so `P_k,D_k <= V Q_k <= V max_k Q_k`, `U_k<=Q_k`, and travel has at most `V+1` evaluated arcs. Before enabling the Round92 row, check `V,M`, `Q`, initial/capacity and vector dimensions, and calculate `uint64_t(V)*uint64_t(maxQ)` with checked multiplication; require the result `<=INT_MAX`. Stored `int` values and these bounds then make the intended route's evaluator counts and binary64 count conversions safe. This is a declared numeric support limit for the candidate, not a cut that removes a lawful tour within that supported domain. Do not infer safety for arbitrary malformed `RoutePlan`: before an R92 witness reaches the existing verifier, a candidate-only structural guard should require distinct in-range vehicle IDs, valid depot endpoints, in-range nonrepeating interior stations, exactly one matching operation per visit and no extra/duplicate operations, and checked 64-bit per-step load/inventory arithmetic. Require the normal legal bounds, then call the unchanged `verifySolution`; malformed or unsupported evidence is an engineering rejection. In particular, `Evaluator.cpp:41–50,72–98,125–133` has `int` accumulators and inventory updates, while its station disjointness check does not reject two separate routes sharing a vehicle. This guard must not claim every historically verifier-accepted malformed vector belongs to the original one-tour problem.

Use a small opt-in API such as `round92RequireProofEnvironment()` and `round92AdmitWitness(instance,routes,lambda,expected_U)`. The first checks the current calling thread's round-to-nearest/gradual-underflow/finite-arithmetic contract; the second calls it, checks the lawful structure with wider integers, runs the *unchanged* physical verifier, and admits only a feasible finite result consistent with the stored witness. Use the newly recomputed objective itself as U; never trust a smaller stale expected_U under a comparison tolerance. In `main.cpp:12993–13002`, apply the admission check to the final seed **after** `runRoutePoolIncumbentMaster` and **before** `cover_hi`, cutoff and `solvePaperExternalGiniTree` are derived; `PaperExternalGiniTree.cpp:2057–2061` should repeat the candidate guard before accepting `verified_seed` as proof input. There is no need to instrument every tentative heuristic call (`main.cpp:12181–12203` and `HgaTgbcRunner.cpp:162,481`), because their output is rechecked at this central boundary. For native outcomes, `PaperExternalGiniTree.cpp:3455–3502` is the shared `backend->solve` wrapper: check the environment before the call, and before an outcome marked `incumbent_independently_verified` can enter any UB/cutoff update, rerun candidate admission and reject the outcome on disagreement or unsafe environment. This covers the visible C6/partial/consolidated/terminal updates at `4090,7666,8079,8473,8724`; final selection/verification at `8891–8895` needs the same check. Since the backend itself uses `verifySolution` to set outcome and feasibility-consistency flags (`GurobiBaseline.cpp:3591–3614`), its two R92-enabled witness-verification sites should use the opt-in guarded API too, or their proof-dependent flags must be revalidated before any native bound is consumed. Do not merely sanitize the route after merging its cutoff or bound. Historical archive-merging paths (`PaperExternalGiniTree.cpp:3238–3251,8884–8890`) must likewise be guarded if reachable with the R92 flag; otherwise prove and gate their inactivity under the isolated preset. These are candidate evidence admissions, not a blanket verifier rewrite or a new feasibility tolerance.

Call `round92RequireProofEnvironment()` on **every** R92 canonical artifact use, before the cache lookup in `CplexBaseline.cpp:488–500` as well as on cache misses; the current check in `Round92HandlingActivation.cpp:149` covers misses only. Call it immediately before candidate physical verification, including the startup seed and native incumbents. Compile both the proof helper and `Evaluator.cpp` for true binary64 evaluation: a compile-time `static_assert(FLT_EVAL_METHOD == 0)` (or explicit equivalent rejected otherwise), no fast-math, reassociation, contraction or excess-precision mode, and preserve actual compiler flags in the candidate identity. The existing helper-only `__FAST_MATH__` check (`Round92HandlingActivation.cpp:12–14`) and one-time volatile fenv probe (`:90–105`) do not establish this for `Evaluator.cpp` or later cache hits. This is an opt-in proof precondition: fail the candidate and its certificate on a violated environment; leave default ENS-C, the canonical duration, and the `1e-7` acceptance rule unchanged. If touching the native backend and seed boundary cannot enforce these premises without broader verification changes, keep the candidate on HOLD rather than silently weakening the theorem.

For the repaired quotient, retain the sign: if `H−ell_low<0`, compute outward `q_hi=(H−ell_low)/c_low` with positive `c_low`; `B=max(0,floor(q_hi))` remains safe (possibly zero), with no absolute value or unsigned cast before the floor. A lower telemetry endpoint uses `ell_hi`, the **same** chosen upper horizon `H` and the **same** positive `c_low`, rounding subtraction/division downward. Agreement of its floor with the upper floor certifies only this deliberately conservative surrogate quotient; it does not certify that `B` is the strongest bound for either the original raw physical or canonical duration system. If `c_low` underflows or is zero, retain the valid no-row case and record its reason.
