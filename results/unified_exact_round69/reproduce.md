# Reproduction and evidence

The solver is exactly Round68's qualified binary and unchanged C++ source.
See build_v1.json for the complete source, main/reference executable, driver,
test-log and qualification hashes. The prior45-test qualification is inherited,
not a newly executed test batch. Build instructions and native qualification
details remain in results/unified_exact_round68/reproduce.md.

Original experiment creation used scripts/round69_research.py freeze once,
then six no-opt reference exports. The immutable plan specifies D3/VD-S300,
E7/S12/N12 with all three arms120, D6 with all three arms3600, and D7 with all
three arms1200. A completed destination cannot be overwritten. The write-ahead
process ledger records attempted launches before execution; every deadline
terminates the whole run. Use scripts/round69_progress.py for a small snapshot.

For new measurements on this qualified local build, use a new output directory:

```powershell
& D:/msys64/ucrt64/bin/python.exe scripts/round69_reproduce.py --output results/round69_fresh_d3 --ids D3 --arms VD-S --cap 300
```

Other permitted roles use their original cap and stage group. The helper
refuses duplicate IDs/arms, mixed caps/stages, a D3 control expansion, changed
binary/source/test bytes, an existing output directory or an active original
queue. It copies the identical qualified build into that fresh output, binds
all reused audit modules explicitly, and creates separate launch evidence.
No such fresh reproduction campaign is counted as an original-stage result.
A rebuild with different bytes requires separate qualification and binding;
it cannot silently inherit these measured timings.

After an optimizer queue has fully stopped, compact evidence is regenerated by:

```powershell
& D:/msys64/ucrt64/bin/python.exe scripts/package_round69.py
& D:/msys64/ucrt64/bin/python.exe scripts/round69_checkpoints.py
& D:/msys64/ucrt64/bin/python.exe scripts/round69_startup_telemetry.py
```

Packaging asserts frozen measured source hashes before completion. Do not run
it after a future C++ revision, or while another optimizer is active. Large raw
models, logs and binaries remain local; compact ledgers, submitted full Start
CSVs and native acceptance logs, verified witnesses, lossless trajectories and
artifact hashes are retained for review. Intermediate P incumbents have native
telemetry scope; the checkpoint table never imports a future final route.
For HGA, round69_hga_provenance.py additionally checks the canonical full route
hash against the published event and retained-candidate result field. A
generation-end timestamp after synchronous verification/copy, with a conservative
epoch/overhead shift, establishes availability. This is independent content
provenance, not an inference from matching objectives. Lossless hga.csv.gz traces
are included in compact evidence; packaging invokes this check automatically.
