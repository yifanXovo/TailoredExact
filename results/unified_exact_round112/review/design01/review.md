# Independent pre-qualification source review

Decision: **HOLD_REQUIRED_STARTUP_WRITE_GUARD** for this interim snapshot. This is source design review, not performance admission. The reviewer started zero native, Optimize and compiler processes. `source_bindings.json` and `source_snapshot/` identify the seven observed files; `production.diff` records the tracked diff. Subsequent production fixes require their own final bindings and actual finite qualification.

Two concrete findings have already been corrected in this snapshot after reviewer feedback: the P-S adapter no longer overrides the original ENS startup seed20260626 with Gurobi Seed0, and `retainOwnStartup` now requires `paid_start_verified`. Without the latter guard, startup revalidation exceptions were followed by publication of the rejected input as a verified own UB. The snapshot contains both fixes and preserves original `round65_witness_audit=true`.

One required fix remains in this snapshot. The new mandatory `<out>.round112.startup.json` is written through `writeTextFile`, whose implementation checks only file opening, allows overwrite, and does not check stream flush/close failure. A failed/truncated required H record can therefore be followed by backend execution. Use an exclusive, checked write for this new mandatory record and finish it before the H-complete phase stamp. A failure must stop the dependent backend; it must not be treated as an optional logging omission. The performance wrapper's new-directory guard remains separately necessary.

The reviewed route shows the intended separation. The compact `opt` remains the isolated plain-gurobi configuration. Only a separate `h` copy is passed through the original R83 preset and `solvePrimalHeuristicDiagnostic -> runPaperPrimalHeuristic`; the original process start/deadline fields are copied and not rebased. The compact writer remains the original `CanonicalCompactModelSpec` with `strengthened=false`. The new opt-in is default-off, mixed research/external flags are rejected, and the ordinary P/ENS/M-B entry points still use the inherited call path.

`round112Submit` reads the actual native matrix before submission: column order/names, LB/UB/VType/Obj, objective constant/sense, every linear row sense/RHS/coefficient and row name, with quadratic/general constructs rejected. It normalizes only within equal-Q classes, adds explicit empty vehicles with their original IDs, maps every actual native column, checks complete linear residuals and objective, submits one full Start, reads the entire native Start back, and rereads the complete matrix before Optimize. It adds no Optimize, LP/presolve job, cutoff row, target stop or StartNodeLimit. The existing R68 callback pointers observe whether a matching vector appears at MIPSOL; they do not submit another Start or activate target behavior. Observation absence must remain distinct from API submission failure.

The mapper change is narrowly scoped: explicit empty `{0,0}` vehicles are accepted, duplicate vehicle IDs are still rejected independently of used/unused status, and empty vehicles do not create `x_kk00` or connection arcs. `normalizeRound61Routes` groups by the actual capacity value before assigning ascending IDs and independently checks unchanged physical inventory/objective. These facts need the requested actual heterogeneous-Q/empty/loaded-return finite qualifications; source review alone does not establish successful native mapping.

The P-S baseline independently replays H before publishing it, retains it if native provides no better feasible fleet, journals it as startup source, uses original zero <=1e-7 with global floor0, and reuses the original absolute work remaining at the sole Optimize launch. It has explicit no-work early returns both before model creation and after Start preparation. The original P default numerical policy and final signed-gap reader remain required; the inherited local relative-gap clamp must not become the scientific signed U-L.

Still unproved before actual qualification: fresh five-role numeric equality against inherited P reference and actual P-S matrices; the exact H100 deterministic trace/full-capacity-aware fleet match across P-S/ENS/M-B; all finite mapping/API failure cases actually executed; startup zero0-Optimize and positive5/24 actual certificates; required outputs and actual whole clocks/fees; PE/DLL/compiler/helper identity; the complete frozen20 argv/order. No formal arm is authorized by this review.
