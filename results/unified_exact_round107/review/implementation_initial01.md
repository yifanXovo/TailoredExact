## Architecture that survives this review

The separate backend preserves the original factory and controller route for every `PaperLpRelaxation`: `makeGurobiFixedIntervalBackend` selects the wrapper; its LP branch delegates the same request to `GurobiFixedIntervalBackend`. There is no new LP oracle or learned-row insertion in that branch. Each integer request reads the actual canonical model, retains its rows, bounds, objective and all other types, and changes only `x_` binary and `load_` integer columns to continuous. The scoped finish is separate from the R106 global finish.

The semantic pool stores the complete name/coefficient map before local column remapping. The pool is inside one backend instance, so it does not transfer proofs from another formal run. Rows are loaded into the candidate pool rather than into a static LP matrix. Raw candidate auditing, unchanged `round106Separate`, conservative travel preparation, compatible A propagation, and unchanged all-station FULL oracle with `core=false` retain the inherited mathematical separation rules. Reliably violated lazy rows are resubmitted at each raw point. The controller changes do not erase AM decisions, leaf milestone or same-epoch child-cache state. Its scheduler remains responsible for global complete-cover aggregation.

`Round107Scope.hpp` correctly distinguishes local INF, local bound dominance and global certification. In particular a local LB above own global UB is not itself an error, and native OPTIMAL below own UB does not close the leaf. That pure decision function does not prove that the wrapper supplies qualified facts; the blockers below concern those facts and the evidence path.

## Required repairs before native qualification

1. **Do not mask an in-domain embedding failure as an absent Start.** `Round107GurobiFrontier.inc:491–498` records a fully mapped witness whose base rows fail as `mapped_witness_base_rows_incompatible` and proceeds with no Start. The mapper documents that a verified original route with in-range true G, cutoff and exact auxiliaries embeds in the retained factory (`MipStartMapping.cpp:304–308`). This branch therefore describes a model/mapping contradiction, not a legitimate out-of-domain witness. Similarly `:303–308` skips every mapper failure during feedback, including unsupported columns, invalid model domain, numerical or mapping failures. Only explicitly verified interval/cutoff incompatibility may skip injection while retaining physical UB. Other mapping failures, residual failures, or objective mismatch must make the current call ERROR and remove new bound/terminal eligibility. Audit the mapped objective dot product as well as bounds, integer columns and all base/proved rows.

2. **Classify ambiguous native status as UNKNOWN.** `:516` omits `GRB_INF_OR_UNBD` from supported statuses, and `:540` turns it into `facts.error`. The requested contract requires no INF proof, no final native attributes and a whole-run open stop for this status. It is not a numerical contradiction merely because a global witness exists. Native no-incumbent/time/deadline and any unrejected UNKNOWN candidate must likewise remain distinct from an audited local INF.

3. **Audit the final native objective for every status.** `:534–535` makes `ObjVal < Ftrue` only set `final_verified=false`. On TIME_LIMIT/INTERRUPTED, `:522` has already promoted the final native bound and the scope helper may still admit a target; ERROR is raised only indirectly on native OPTIMAL. A below-true objective is an ERROR for the whole current request under the required contract. Independently recompute true F from final integer Y, recompute objective coefficients/constant against the exact final X, and reject any inconsistent objective regardless of native status or physical-cache availability. Preserve a separately verified physical UB, but strip all new local bound events, target and native terminal bits.

4. **Post-cancellation candidates must not bypass UNKNOWN priority.** `:339` stops examining every callback after `outer_cancelled`, including MIPSOL delivered after a target terminate request. `:347` can therefore freeze target success before a later unaudited candidate is seen. Either continue the same physical audit at such a delivered MIPSOL, without starting a new call after deadline, or conservatively mark that unresolved delivered candidate and exclude later final attributes/target. A later unrejected UNKNOWN must outrank an earlier target observation. Preserve separate request/observed/native-return/qualified-target evidence.

5. **Track every actually embedded in-domain physical witness.** `:542` supplies `domain_witness_embeds = !start.empty()` only. A later all-car FEAS route may fully map and satisfy all current base/proved rows even when the initial global witness was outside I or a strict cutoff. That mathematical embedding contradicts subsequent native INF independently of whether `cbsolution` was deferred, observed or accepted. Retain a request-local `domain_witness_embeds` fact once any such complete witness is audited. Do not infer that fact solely from true-G membership without a full embedding audit.

6. **Prove every missing selector is zero in the actual current domain.** `:128–136` parses station/value and checks physical capacity, then labels every absent `state_i_y` fixed zero. It does not check that y is outside the actual integer Y bounds or otherwise absent only because of a proved current selector domain. The original VD-P writer creates exactly all integer states from actual `y_lb` through `y_ub` (`CplexBaseline.cpp:937–951`); this permits a direct checked certificate. Missing a state inside those bounds is a model/domain error, not permission to delete a semantic term. Log actual current Y bounds and the reason for omission; also check the retained Y/state/ownership/direction/pickup/delivery integer type contract, including required selector completeness. Retain full semantic rows for future expanded domains.

7. **Record actual paid calls and resource lifecycle even when they fail.** `:574–584` updates all extra environment/model/read/master-Optimize counters only after final audit and persistence succeed. An error thrown after Optimize at `:513`, including numeric audit, final-vector audit or persistence failure, reaches `:585–589` without accounting for the actual call and without completing the already begun outer journal call (`:510–511`). The R105 per-session `calls.csv` can retain the paid call, but public backend lifecycle then disagrees. Count real creations/reads/Optimize starts and frees at the actual operations or in guaranteed scope finalizers, preserving failed attempts. Do not hardcode successful model/free totals from the number of oracle Optimizes: an inner model can be created/read and then fail or run out of remaining time before its Optimize. The after-setup deadline path of `R105Session::optimize` returns TIME_LIMIT without native Optimize; that must not be logged as one paid master call. Always finalize begun journal records with the actual return/error status. Clear `native_exact_optimal` and every terminal bit on later catch paths too.

8. **Keep early open-stop causes truthful in the controller.** The new `round107_unresolved_stop` field has no controller consumer. The partial path labels every interruption `deadline_open` and calls `stopAtDeadline` (`PaperExternalGiniTree.cpp:4345–4356`); the terminal decision/path labels every interruption as global deadline and calls the same helper (`:1137–1140`, `:8907–8917`). That helper sets `overall_global_deadline`, increments deadline count and marks deadline even when the actual reason is early oracle UNKNOWN or native OPTIMAL without closure. Add a candidate-specific whole-run open-stop cause while retaining the same complete obligations and qualified pre-stop LB/UB. Do not fabricate elapsed-deadline evidence, requeue a questionable request or allow a new Optimize after the safe stop.

9. **Enforce the unchanged ENS-C contract at CLI admission.** The new guard (`main.cpp:3386–3396`) checks fewer isolation conditions than the inherited R106 guard (`:3401–3433`). It permits altered method/K1 controller, scheduling, startup settings, external incumbents, Gini cap/floor and optional route/resource/cut features omitted from this new guard. These can create a hybrid or restricted-root run while retaining the R107 identity. Require the original method/controller/scheduling/full-root/preset startup settings and reject incompatible optional modifications or imported witnesses. Ordinary frozen run parameters such as instance, budget, seed and artifact destination remain allowed.

## Evidence and qualification requirements that remain open

The first native test source has direct terminal, strict-empty-domain, outside-witness and controller fixtures, but its controller assertion only checks lack of a failure reason. It does not require an actual partial native target request/observation/termination, qualified controller requeue/milestone and subsequent terminal or split. The pure scope examples are necessary examples, not native tests. Before performance admission I need raw canonical/master matrices and variable types, snapshots/events, full physical proofs, submissions and exact final accepted service mode, actual caller/controller target transition, runtime/PE/DLL SHA and parameter/LazyConstraints readbacks, all engineering receipts and actual native call totals.

The raw source must also distinguish first semantic proof from regenerated arithmetic proof, row remapping, ordinary/cross-request cache hit and actual lazy submission. `structural_proofs` currently counts every returned certificate even if `remember` finds an existing full semantic row. Existing semantic row records identify family/vehicle/origin request but do not directly identify the originating event/certificate/native proof path; that link must be reconstructible and independently checked. Current paid-startup labeling is refreshed from each request's current own witness, so later physical improvements should retain their own provenance rather than being mislabeled as startup proofs.

The LP branch currently reports cutoff presence from a scalar condition instead of reading actual canonical row evidence. When the original model has no objective cutoff (zero/lambda-zero), the integer branch leaves a finite submission-filter cutoff in `effective_cutoff`; the report must separately identify actual row absence and this conservative mapper filter. No artificial row/epsilon may be inferred from it. Likewise setup-inclusive `model_read_seconds` and unchecked Work/iteration attribute reads require truthful labels and missing-data handling; `BarIterCount` is an integer attribute, so a double-attribute lookup must not silently record zero.

`R105Session::optimize` does perform inherited parameter readback before Optimize, native log numerical-warning checks, numerical status rejection, final raw matrix residual and quality checks. This review does not mistake their absence in the wrapper for absence of those inherited gates. The review still requires real qualification evidence and status-correct exclusion of final attributes on UNKNOWN/error, including an accurate `final_native_bound_qualified` predicate rather than merely `!state.error && !state.unresolved && final_b`.

The inherited R92 finiteness argument remains conditional on successful finite native/LP returns or whole-run stop. This wrapper introduces no new candidate restart, but qualification must show the actual original finite controller transition, not infer it from the pure decision helper or from one successful terminal solve. No performance ranking, candidate certification, or native termination guarantee is approved by this initial review.
