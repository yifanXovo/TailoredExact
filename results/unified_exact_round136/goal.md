必要的数学解释保留即可：对同一固定域、同一目标的连续松弛，
\[
\mathcal R_{\rm AP}\subseteq\mathcal R_0
\quad\Longrightarrow\quad
\min_{x\in\mathcal R_{\rm AP}}f(x)\ge
\min_{x\in\mathcal R_0}f(x).
\]
这是可行集包含关系的直接结果。有限计算时限内的完整算法则可能经历不同的分支、割、启发式和区间处理序列，不能由此推出
\[
L_{\rm AP}(t)\ge L_{\rm S2}(t)
\quad\text{或}\quad
T_{\rm AP}^{\rm cert}\le T_{\rm S2}^{\rm cert}.
\]
因此 K35 的强根与较弱截止下界可以同时成立，不构成正确性 bug 的证据。当前数据也不足以断言某个具体原生分支或割就是原因，不再为此补归因实验。

- 复核 Git 祖先关系、当前配置与源码身份、文档/论文链接、PR/ref 处置清单。
- 若有薄 launcher，先做完整 argv/config dry-run 比对；必要时用微型输入与 UC-B20-B 做少量端到端 smoke，**native 总预算不超过 600 秒**，输出写新目录。
- 默认新增 native 求解为 0；smoke 只验证入口和产物，不充作新性能样本，不要求重复得到逐位相同耗时或树轨迹。
- 文档/归档整理不触发生产重编译、全套测试或正式面板。仅出现明确入口/构建问题时做对应检查。
- R135 公开恢复已经通过；本轮只检查新增入口及所需小文件可访问，不重做 32 臂 raw 恢复，更不重建全历史。

### G2. 默认资源安排

| 工作 | 建议主动时间 |
|---|---:|
| 元数据、本地盘点与依赖确认 | 30–45 分钟 |
| 当前入口、文档与整合 PR | 45–75 分钟 |
| 明确对象的本地整理 | 30–60 分钟 |
| 论文交接与独立复核 | 30–45 分钟 |

这是工作量规划，不是算法规则或机械壁钟门槛。慢 I/O、必要的一次具体修正可合理调整并记录，不自动扩展为多轮维护工程。600 秒 native smoke 单独记录且包含完整自身 H；不重复累计嵌套 LP/MIP。

## H. 交付与完成状态

交付可以合并为少量文件，不以文件数量衡量完成：

- 当前主线/发布清单、简洁 README 和必要运行入口；
- PR/分支祖先关系与处置清单，独立 R38 归档说明；
- 实际本地盘点、清理结果及保留依赖；
- 最新论文审阅入口、短交接说明、作者待确认表；
- 入口/身份检查与独立复核结果；
- 目标 main 的英文整合 PR，以及实际 base/head；
- 获准后实际 merge/关闭结果；未获准时给出一份具体最终确认请求。

“已完成准备”与“main 已实际更新”分别报告。没有合并授权时，可以完成除最后操作外的全部可做事项；获得既有授权时应继续做完，不重复询问。

最终报告回答：

1. 当前应该使用哪个版本、哪个命令、哪个稿件？
2. GitHub 主线整合到了哪一步，旧 PR 如何处置，独立历史是否保留？
3. 本地实际整理了什么、节省多少空间、哪些依赖继续保留？
4. S2 的算法和已验收证据是否保持？
5. 论文下一步需要作者/导师做出的具体判断是什么？

**成功标准：当前算法与稿件有唯一清楚入口，main 整合准备完整或按授权完成，旧 PR 和本地副本得到适度整理，历史证据可追溯；无需通过新算法正结果证明本轮价值。**
