# A2 proposal: an integral quantity oracle on fixed routes

Status: coordinator derivation independently reviewed in `a2_network_quantity_independent_review.md`, with the domain qualifications below. It is not implemented, not a replacement for the frozen ENS-C, and has no real-instance performance evidence. Motivation: a single constructive seed loses D6 startup quality, whereas Round75 already exhausted individual/pair quantity edits. This proposal changes the joint quantity oracle without introducing a learning rate, a seed-count replacement or a component resource budget.

## Network representation and assumptions

Fix the current vehicle assignment and relative visit order; each station occurs on at most one route. Vehicles start empty, end at the depot and may return loaded, as in the original model. Let b_i and C_i denote original inventory and capacity. For vehicle k let travel_k be its current full-template travel, Q_k its load capacity and T_k its route limit. Pickup/drop service times c_p,c_d are the original common nonnegative constants. In the nominal mathematical model, require travel_k<=T_k. When c_p+c_d>0, define the mathematically derived integer bound K_k=floor((T_k-travel_k)/(c_p+c_d)); when their sum is zero, use the finite sum of b_i on that route instead, still checking travel_k<=T_k. A negative K_k means that full template is inapplicable, not that the original BRP instance is infeasible.

The current witness must itself belong to this declared network domain before the segment proof is used. A verifier-accepted witness can be outside a nominal floor at a numerical boundary, since the existing duration acceptance has tolerance 1e-7. Implementation must explicitly distinguish the nominal theorem from that unchanged numerical convention, derive the integer budget conservatively, and check the current point; it must not silently raise the original tolerance, assert coverage of all tolerance-accepted states, or enlarge the budget merely to obtain a proposal. A numerical domain rejection preserves the current verified state and records the reason. The final original verifier remains mandatory.

Construct a circulation network with source node s, disposal node t, one budget node v_k per vehicle, and one node for each ordered visit. Add:

1. s -> v_k with capacity K_k;
2. v_k -> visit(i) with capacity b_i, representing pickups p_i;
3. visit(i) -> t with capacity C_i-b_i, representing drops d_i;
4. consecutive visit arcs with capacity Q_k, representing carried load after a visit;
5. last visit -> t with capacity Q_k, representing loaded return;
6. t -> s with capacity sum_i b_i, closing the circulation.

All lower capacities are zero. Empty routes require no visit arcs. At every visit, conservation is L_before+p_i=L_after+d_i. Hence an integer circulation gives all original prefix load bounds and Y_i=b_i-p_i+d_i in [0,C_i]. The budget gives sum p_i<=K_k. If both p_i and d_i are positive, cancel min(p_i,d_i). This leaves inventories, all carried loads and any linear net-inventory objective unchanged and weakly decreases gross pickup/service cost. It produces a valid unidirectional operation at each station. Delete zero-net visits before physical verification. Under an exact metric assumption, deletion cannot increase travel. Thus the projected physical route is feasible; its handling plus loaded-return cost is (c_p+c_d) times the remaining total pickups after cancellation.

ENS-C's CLI already checks symmetric metric travel through `hasMetricTravelLowerBounds` in `PaperK1AmSf.cpp`, called for the R83 preset in `main.cpp`. That check has a numerical tolerance; it does not remove the need to verify actual shortened-route duration. The generic parser and a standalone oracle do not inherit this contract automatically. For nonmetric matrices, the network is still an exact linear oracle for the stated full-template quantity set, but deleting zero visits can increase travel and destroy physical feasibility. Such use must not be advertised as an unconditional physical projection; the independent review gives an explicit counterexample.

Conversely, any integer quantity assignment satisfying the same fixed-template travel bound and original prefix constraints has such a circulation: route pickups through its budget node, route loads through prefix arcs, station drops and returned stock to t, and total pickup through t -> s. This characterizes that explicitly restricted quantity set. It does not include every feasible assignment that could exploit travel saved by deleting visits; after an accepted deletion a subsequent pass may recompute the smaller template. The network does not add new visits or change assignments.

## Exact linear quantity oracle

For any station weights g_i, minimizing sum_i g_i(Y_i-Y_i_current) is a min-cost circulation: pickup arc cost -g_i, drop arc cost +g_i, other costs zero. Integer capacities admit an integer optimum. A self-contained certificate is absence of a negative-cost residual cycle: the difference between any two feasible circulations decomposes into residual cycles, so no such cycle proves linear optimality. Starting from an integer circulation and augmenting integer bottleneck quantities preserves integrality. With exact rational costs, strict negative-cycle improvement terminates because there are finitely many bounded integer flows. This statement gives no practical runtime bound for a particular cycle-cancellation implementation.

A possible deterministic weight choice, at S=sum_i Y_i/D_i>0, uses the original objective's gradient where differentiable and the explicit zero-sign subgradient at ties. Let H=sum_{i<j}|r_i-r_j| and r_i=Y_i/D_i. Then

g_i = [S sum_{j!=i} sign(r_i-r_j) - H]/(n S^2 D_i) + lambda w_i sign(r_i-1)/D_i.

The resulting joint inventory proposal is an integral minimizer of this linearization. It is **not** necessarily an improving move for the nonlinear or nonsmooth original F. If its inventory difference is identically zero, return `no_direction`. Otherwise take the primitive integer direction by dividing all inventory differences by their positive gcd, and use the separately reviewed exact scalar-search proposal to test the finite segment between current and proposed quantities. Prefix-load and inventory bounds remain feasible on this segment. Gross pickup is a sum of positive parts and therefore convex along it, so the same full-template service bound also holds, provided both endpoints belong to that domain. The actual selected route still requires independent original-objective/physical verification.

Accept only an original verified strict F improvement and repeat on the resulting template. Stop if the oracle/line segment yields no improvement. At S=0, retain the original verified state and return `no_gradient_at_zero`: the original special convention is not a continuous differentiable extension, so the gradient formula is inapplicable. This is a mathematical boundary rule, not a resource-triggered alternate solver. Finite physical integer states and strict verified descent prevent cycling under the declared numerical acceptance semantics. This is a conditional-gradient-inspired **proposal heuristic**, not a proof of neighborhood exhaustion, stationarity, convexity, global optimality or P-GRB superiority. A zero-sign choice at a nonsmooth tie can miss useful directions; that is a limitation to diagnose, not grounds for claiming local optimality.

## Independent review / diagnostic gate

Check the common budget-node construction, cancellation, loaded returns, metric deletion, zero service time, heterogeneous Q, and the converse projection with exhaustive tiny fixed-route quantity enumeration. Compare the linear optimum and witness against an independent enumerator. Verify the derivative, gcd segment, conservative duration arithmetic and original objective acceptance. The diagnostic must differ concretely from Round75's already exhausted pair neighborhood. Only after those proofs and fixtures should it be tried on preserved D6/D7/U6/F5/F6 endpoints as an offline mechanism probe; archived routes must never become formal algorithm inputs. The practical choice of exact network solver and its full counted cost remain open.

Independent review supplies a concrete three-station witness: Q=3, b=(4,1,4), C=(4,4,6), D=(3,3,1), lambda=2, current net pickups (1,-1,2). Its F=32/11 cannot improve through the reviewed single/pair neighborhood, whereas this gradient's unique linear-oracle optimum has net pickups (0,0,3) and original F=9/4. The line has gcd=1 and is physically feasible under the stated metric/time fixture. This proves that the joint proposal can reach an improvement missed by that neighborhood; it is not a real-instance speed or success result. Preserve a runnable exhaustive fixture before implementation qualification.
