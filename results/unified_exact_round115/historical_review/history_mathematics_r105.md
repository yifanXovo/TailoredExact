## Exact route and conflict scope

For a fixed vehicle mode, all selected stations must have one nonzero directed integer operation, all absent ones zero, and quantities must agree with b-Y and the unique integer z/m assignment. In a reduced checker, include the depot and **every** selected station with all original directed arcs and all visit orders. No selected stop can be silently deleted. Since original semantics prohibit zero-service visits and repeats, absent stations cannot act as uncharged travel intermediaries in that fixed exact mode. Use original arcs rather than shortest-path replacements for witness travel.

An all-order single-route arc/order/load MIP with fixed operations is bidirectionally equivalent: every physical route induces its variables; binary degree/connectivity/order conditions recover one depot tour; recurrence gives its prefix loads; the full duration row uses travel+(cp+cd)*sum pickup. Continuous load is sufficient when route arcs and operations are integral, because active recurrences give integer loads. The generic free-station template for core extraction is a **different** model: all stations retained, only this car's physical rows, unrestricted legal local quantities/visits, no global objective/cutoff/other-car obligations. Released absence assumptions must actually restore station variables/arcs/service possibilities.

Fixed local nonservice is represented by z_ki=0, without fixing global Y_i. A fixed served operation maps to **both** z_ki=1 and state(i,y)=1; quantity fixation in the oracle cannot become a global-Y-only literal, even if its IIS row already implies local visit. Conservatively keep all technical rows/bounds belonging to an assumption group when any portion of the group occurs in an IIS.

For proved infeasible complete mode S, the requested mismatch expression is nonnegative and zero exactly when its membership and every served quantity remain identical. The row Delta>=1 excludes the current infeasible local mode while permitting quantity changes, reassignment and extra auxiliary service. The absence sum over i outside S is essential. The current row should be evaluated at the saved master vector and shown violated. It is not a global inventory no-good: an alternate allocation of the same Y can route.

The capacity counterexample is a direct proof: for Q=3 and (+2,+2,-3), the first move must be +2; either second move causes load 4 or -1, so no permutation works. Adding -1 admits (+2,-1,+2,-3) with loads (2,1,3,0). Therefore positive served-subset literals alone are unsafe. For example A, single service forces the only supplier's pickup4 onto one vehicle; empty departure forces all four deliveries onto it. Five visited stations have travel 1+4*2+1=10 and handling8, totaling18>T16. The necessary singleton/triple resource bounds do not capture this complete route. These deductions still require independent executable qualification in the main task.

A smaller core must be re-proved in the complete generic template after **all other** assumptions are removed. It may include both positive and negative literals. Translating conjunction assumptions to z/state literals gives sum(L)<=|C|-1; retain both literals for each served operation. Empty-assumption template should admit an empty route for valid nonnegative inputs; an empty extracted core is an error signal. Do not infer monotonicity in amount, supersets, Q/T or vehicle labels without a separate proof. Cache keys must bind all local operations and physical Q/T/handling/travel/numerical inputs, even if source Y is unchanged.

Only actual INFEASIBLE or an accepted reliable minimax-time lower bound above T can prove failure. A feasible route passing the **original** physical horizon suffices without shortest-route optimality. UNKNOWN/ERROR produce no conflict. [Gurobi status documentation](https://docs.gurobi.com/projects/optimizer/en/current/reference/numericcodes/statuscodes.html) distinguishes INFEASIBLE from INF_OR_UNBD and limit statuses. [The installed-version family C API reference](https://docs.gurobi.com/projects/optimizer/en/current/reference/c/solving.html) permits MIP IIS, considers termination parameters, and says early interruption returns the smallest infeasible subsystem found so far; IISMinimal concerns irreducibility, not minimum cardinality or mapping validity. Recheck the semantic core to avoid relying on that field alone. [Gurobi's IIS guide](https://support.gurobi.com/hc/en-us/articles/15656630439441-How-do-I-use-compute-IIS-to-find-a-subset-of-constraints-that-are-causing-model-infeasibility) requires inspection of row and variable-bound membership. These are floating native proofs in specified scope, not rational Farkas proofs for integer route infeasibility.

## Global loop, witnesses and admission boundary

The proposed outer loop is exact conditional on the above contracts: M includes every original optimum; each retained conflict excludes no original solution; qualified master ObjBound is an original-objective lower bound; a complete verified route set supplies the original UB. Finitely many inventory/assignment modes exist. Every infeasible iteration excludes its current complete local mode, and hence its current fleet candidate; all-feasible optimal candidates must close against their master optimum. A repeated unchanged mode after an accepted row signals extraction/update/tolerance error, not a reason for an arbitrary iteration cap. A nonoptimal interrupted master can retain a qualified bound, but its incumbent objective is no original UB until routes validate. No subproblem time value/zero objective/local infeasibility is an F lower bound.

Keep the strongest qualified old master bounds after adding valid conflicts. A master becoming infeasible while the non-strict known witness still embeds, or an LB materially above verified U, is an error signal. Do not hide it by min(U,LB) clipping or treat it as a certificate shortcut. Whole-run deadline interrupts master, oracle and IIS; UNKNOWN ends the exact run with existing genuine bounds/witness, without excluding that mode, restarting on a timer or switching to ENS.

Use the strict complete witness wrapper or equivalent checks for UB: `src/PhysicalWitnessValidation.cpp:39–65` requires exactly one route per vehicle, no duplicate vehicle, one operation per visited station and unique stations. Plain `verifySolution` at `src/Evaluator.cpp:33` alone permits missing/duplicate vehicle route records and does not reject duplicate operation records for an already visited station. Mapper `src/MipStartMapping.cpp:117–125` rejects explicit empty [0,0] because it is a self arc, while the complete physical wrapper expects all vehicles. Deliberately normalize between full physical route lists and sparse mapper route lists; R61 already encountered this representation mismatch. All-column Start mapping at `src/MipStartMapping.cpp:241–276` reconstructs state/G product variables, but its returned semantic row flag is not a substitute for independently recomputing actual native row residuals.
