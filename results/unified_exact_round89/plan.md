# Round89: native inventory-CDF B1 user cuts

The approved overall research goal remains active. This round starts in the same `E:/codes/ExactEBRP` checkout from Round88 commit `247cf16b8`, on `codex/round89-ensc-native-ot-b1`. It is a narrow default-off prototype, not a mainline change or a long-run campaign.

## Hypothesis and boundary

Round88 established B1/B2 validity and observable LP strengthening, but neither an external repeated-LP service nor an eager full-family epigraph earned production advancement. Native branch-and-cut is structurally different: it can separate original-column B1 rows at already-occurring optimal MIPNODE events, without launching another Optimize or prebuilding every epigraph row. Whether that saves enough work is unresolved. Only B1 is admitted here; there is no B2 or parameter-grid extension.

The implementation must follow the independently reviewed [actual-model contract](../unified_exact_round88/native_ot_b1_contract_review.md) and [Gurobi API notes](../unified_exact_round88/native_ot_api_reference_notes.md). Source review corrected an early interface assumption: ENS-C VD-P uses two equalities, `r_i=alpha_i*y_i` and `y_i=sum_y y*state_i_y`; the direct ratio/state equality belongs to VD-J. Therefore audit the actual two-link coefficients. Their exact product need not fit in binary64: rounded support knots carry outward product-error bounds, included in the conservative RHS together with cut-coefficient rounding errors. This prevents an implementation from treating a rounded product as the exact model support. Cached merged supports and a linear prefix/suffix separation pass generate one signed row per station pair. Outward activity arithmetic reliably detects violation against unchanged native feasibility tolerance. Any sign pattern is integer-valid; an imperfect callback point is not a license to alter the model or reject a solver result.

The same rule must cover terminal and partial-bound native proof MIPs. Ordinary LP probes are deliberately unchanged. Preserve global deadlines, mathematical target stops, coverage, verified starts, progress and physical certification. Set and record PreCrush=1 only for this candidate. Do not change CutPasses, native tolerances, startup, AM gate, split depth or unrelated solver parameters. There are no internal time/Work/row/pass quotas and no timed fallback. Successful cut submission means only API success, not permanent activity. Deduplicate within one callback; repeated reliable violations in later callbacks may be resubmitted.

## Work and admission sequence

1. Sol implementation (high) owns the minimal C++ separator, adapter and tests. Root owns Git. Sol mathematics (xhigh) independently reviews exact-row validity, outward arithmetic, actual-column identity and preservation of proof semantics. Source edits have one owner; build and heavy execution have one computation slot.
2. Freeze the implementation before executable qualification. First check a finite pure support/sign oracle, including collisions, adjacent doubles, near-zero and invalid arithmetic; compare native coefficients to an independent exact-dyadic oracle. Then run one isolated native toy in off/static/callback modes, checking integer objective agreement and actual callback cut submission. A deliberately declared toy-only configuration may expose a fractional root; production parameters may not inherit those artificial settings. Exercise terminal and partial-bound paths and confirm ordinary LP remains outside the callback. Focused existing tests protect unchanged defaults, deadline and evidence behavior. Keep all failed attempts and repair scope.
3. Root examines qualification and admits a separately specified bounded real-source mechanism screen only if the callback is valid and actually exercised. Numerical validity alone is not a speed claim. Complete-method G3 admission, if justified, uses the existing approved instance roles and whole-run cutoffs with contemporaneous ENS-C comparisons where needed; P-GRB remains the original independent benchmark. No automatic long test starts from passing a unit test.
4. If the callback cannot be qualified or its bounded evidence fails to justify cost, park native OT integration and proceed to the remaining split/engineering hypotheses. Do not keep extending deadlines or adding cut variants merely to obtain a positive outcome.
